# 가이드 운영 런북

작성일: 2026-08-03

이 문서는 기준체크의 건강보험 가이드 6편을 검색 유입과 제도 변경에 맞춰 운영하기 위한
반복 절차다. 새 글을 늘리기 전에 기존 글의 출처·최신성·다음 행동을 먼저 유지한다.

## 운영 대상

현재 운영 가이드는 다음 6편이다.

- 피부양자 자격상실과 지역가입자 전환
- 피부양자 등록 전 확인할 것
- 재산세 과세표준 확인 방법
- 국민연금이 피부양자 자격에 미치는 영향
- 11월 건강보험료 재산정
- 임의계속가입이 유리한 경우

## 주간 점검

검색 데이터가 안정될 때까지 매주 한 번 아래 항목을 확인한다.

1. Search Console과 네이버 서치어드바이저에서 가이드별 색인·제외·canonical 상태를 확인한다.
2. 검색어와 랜딩 페이지를 확인해 기존 FAQ로 답할 수 있는 반복 질문을 모은다.
3. GA4에서 가이드 진입 후 도구 이동, 공식 출처 클릭, 이탈이 두드러지는 페이지를 확인한다.
4. 외부 출처 링크가 열리고, 법령·공단 안내의 기준일이 현재 문구와 맞는지 확인한다.

검색 데이터가 안정된 뒤에는 색인 상태는 주간, 성과·질문 분석은 월간으로 전환한다.

## 색인·실적 점검 절차

> 2026-08-06 추가. 위 「주간 점검」 1·2번을 **실제로 실행 가능한 순서**로 푼 것이다.
> 이 절이 없던 동안 매번 방법을 다시 찾았고, 아래 함정 세 개를 실제로 밟았다.

### 0. 먼저 읽을 것 — 세 가지 함정

**① `site:` 결과는 10개에서 잘린다.**

Google이 `num` 파라미터를 더 이상 받지 않는다. `&filter=0`(생략 결과 포함)을 붙여도
**한 페이지에 10개까지만 나온다.** 1페이지만 보고 "미색인"으로 판정하면 틀린다.
반드시 페이지 끝까지 넘기거나 `&start=10` 으로 다음 페이지를 확인한다.

```
https://www.google.com/search?q=site:gijuncheck.kr&filter=0
https://www.google.com/search?q=site:gijuncheck.kr&filter=0&start=10
```

**② 리다이렉트를 브라우저로 확인하지 않는다.**

`vercel.json` 이 `Strict-Transport-Security ... preload` 를 보내므로, 한 번 https를
방문한 브라우저는 **서버에 묻지 않고 스스로 https로 올린다.** 주소창에 http를 쳐서
https로 바뀌는 것은 서버 동작의 증거가 아니다. HSTS는 브라우저용 신호이고 Googlebot의
URL 정규화를 대신하지 않는다. 반드시 명령줄로 응답 코드를 본다.

```
curl -I http://gijuncheck.kr/        # 301 또는 308 + Location: https://... 이어야 정상
```

**③ `site:` 는 GSC를 대체하지 않는다.**

`site:` 는 **색인 여부만** 보여준다. 제외 사유·선택 canonical·노출·클릭·검색어는
전부 GSC에서만 확인된다. 이상하면 반드시 GSC URL 검사로 교차 확인한다.

### 1. 색인 상태 (주간, 5분)

1. `site:gijuncheck.kr` 을 **2페이지까지** 확인한다
2. 색인 대상 수와 대조한다 — `src/lib/routes.ts` 의 `indexableRoutes()`
   (= `ready: true` 이면서 `noindex` 아님). **2026-08-06 기준 11개**
3. 빠진 URL이 있으면 GSC **URL 검사**에 전체 URL을 넣는다.
   `trailingSlash: true` 이므로 **끝 슬래시까지 정확히** 넣는다
4. 「페이지 색인 생성」을 펼쳐 아래를 읽는다

| 항목 | 정상값 | 이상하면 |
|---|---|---|
| 크롤링 허용 여부 | 예 | `robots.ts` · `SITE.indexable` 확인 |
| 페이지 가져오기 | 성공 | 배포·도메인 상태 확인 |
| 색인 생성 허용 여부 | 예 | 해당 라우트의 `noindex` 확인 |
| 사용자 선언 표준 URL | 자기 자신(절대 https) | `createPageMetadata` 의 `alternates` 확인 |
| **Google에서 선택한 표준 URL** | **검사된 URL** | 다른 URL이면 중복 판정 — 콘텐츠 차별화 문제 |

5. 제외 사유별 대응

| GSC 상태 | 의미 | 대응 |
|---|---|---|
| 발견됨 – 색인 생성되지 않음 | 크롤을 안 옴 (크롤 예산) | 내부 링크 보강 |
| 크롤링됨 – 색인 생성되지 않음 | 읽고 나서 제외 (품질 판단) | 콘텐츠 보강·중복 확인 |
| 대체 페이지(적절한 표준 태그 있음) | 다른 URL의 중복 처리 | canonical 충돌. 주제 겹치는 페이지 확인 |
| 페이지에 리디렉션 있음 | URL 형태 불일치 | 슬래시·프로토콜 확인 |

### 2. 색인 생성 요청 기준

**이미 색인된 URL에 다시 요청하지 않는다.** 순위가 오르지 않고 일일 할당량만 쓴다.
요청은 재크롤 유도이지 순위 개선 장치가 아니다.

요청하는 경우는 두 가지뿐이다.

- 아직 색인되지 않은 URL
- 콘텐츠가 **의미 있게** 바뀐 URL (오탈자 수정은 해당 없음)

평상시 재크롤 신호는 수동 요청이 아니라 아래 자동 경로로 나간다.

```
src/lib/routes.ts 의 lastModified 갱신
  → src/app/sitemap.ts 의 lastmod
  → 검색엔진 재크롤 신호
```

**페이지 내용이나 기준을 바꿨으면 `lastModified` 를 함께 갱신한다.** 이것이 기본 경로이고,
수동 요청은 급할 때 쓰는 보조 수단이다.

### 3. 네이버

네이버는 `site:` 결과가 불완전하다. **결과가 비어 있다는 것만으로 미색인으로 단정하지
않는다.** 서치어드바이저를 1차 수단으로 한다.

- **요청 → 웹 페이지 수집** — URL 단위 수집 요청 (일일 요청 수 제한 있음)
- **검증 → 웹 페이지 최적화** — GSC의 URL 검사에 대응. title·description·robots 진단
- **요청 → 사이트맵 제출** — `sitemap.xml` 제출 상태
- **리포트 → 사이트 최적화 / 수집 현황** — 전체 그림

반영이 Google보다 느리다. 수집 요청 후 며칠 뒤에 확인하고, **반복 요청하지 않는다.**

### 4. 실적 (주간은 생존 확인, 판단은 월간)

GSC **실적 → 검색결과**에서 기간을 넓히고 **검색어 탭**을 본다.
필요하면 내보내기로 저장하고 `docs/06-QA-전수점검.md` 에 기준선과 함께 기록한다.

주간에 볼 것은 증감이 아니라 **생존 신호**다.

- 노출이 계속 잡히고 있는가
- 노출되는 페이지가 늘고 있는가
- 도구 페이지가 노출되기 시작했는가 (현재는 가이드만 노출된다)

**검색어 시트가 비어 있는 것은 정상이다.** GSC는 익명화 기준 미만의 질의를 감춘다.
노출이 수십~수백 단위가 되어야 질의가 보이기 시작한다. 버그로 오해하지 않는다.

**주간 데이터의 증감으로 전략을 바꾸지 않는다.** 판단 시점은
`docs/09-A안-90일-실행계획.md` 6절의 선행 지표 확인 시점이다.

## 월간 콘텐츠 점검

매월 첫 운영 점검 때 가이드별로 아래 항목을 기록한다.

| 점검 항목 | 기록할 내용 |
| --- | --- |
| 검색 질문 | 실제 검색어 또는 반복 문의를 한 문장으로 요약 |
| 첫 답변 | 제목·리드·한 줄 답변이 질문에 바로 답하는지 |
| 기준일 | 기준 연도와 최종 확인일 |
| 공식 근거 | 법령·공단·정부 기관 링크와 변경 여부 |
| 예외·한계 | 단순 계산으로 판단할 수 없는 개인별 조건 |
| 다음 행동 | 관련 계산기, 확인 서류, 공단 문의 질문 |
| 내부 링크 | 관련 가이드와 도구 링크가 현재 유효한지 |

## 제도 변경 대응 순서

숫자나 문구만 먼저 고치지 않는다. 다음 순서를 하나의 변경 작업으로 처리한다.

1. 법제처·국민건강보험공단 등 공식 출처에서 변경 내용과 시행일을 확인한다.
2. 상수와 판정·계산 로직을 변경한다.
3. 가이드 본문, FAQ, 한 줄 답변, 면책 문구를 함께 갱신한다.
4. 단위 테스트와 가이드 품질 E2E를 실행한다.
5. `docs/03-검증기록.md`에 확인 범위·공식 대조 여부·미확인 범위를 기록한다.
6. 배포 후 최종 도메인과 모바일에서 해당 가이드·도구 동선을 확인한다.

## 새 가이드 추가 기준

다음 조건을 모두 만족할 때만 새 가이드를 검토한다.

- 실제 검색어 또는 반복 문의가 확인됐다.
- 최신 공식 출처를 최소 1개 이상 확보했다.
- 한 줄 답변, FAQ, 예외·한계, 다음 행동을 작성할 수 있다.
- 관련 도구 또는 기존 가이드로 연결되는 내부 링크가 있다.
- 대표 사례 테스트와 검증기록을 추가할 수 있다.

출처가 불명확하거나 검색 데이터가 없는 주제는 초안 목록에만 남기고 공개하지 않는다.

## 수정 우선순위

1. 잘못된 법령·공단 기준 또는 깨진 공식 출처
2. 실제 계산 결과를 바꿀 수 있는 숫자·분기 오류
3. 모바일에서 잘리는 표·출처·FAQ와 막힌 내부 링크
4. 검색 질문과 맞지 않는 제목·첫 답변
5. 표현·예시·내부 링크 개선
