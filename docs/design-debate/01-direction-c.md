# 방향 C: 판정 근거의 정확성과 추적 가능성을 최대화하는 레퍼런스형 판정 도구

## 0. 이 안의 목적함수
사용자가 판정 결과를 스스로 재현·검증할 수 있도록, 법령 근거·계산 과정·적용 조건의 추적 가능성을 최대화한다.

## 1. 거부한 전제

| Brief의 전제 # | 거부 이유 |
|---|---|
| 4 | "단일 화면 배치가 이탈을 줄인다"는 전제는 전환율(완료율)을 목표함수로 삼을 때만 의미가 있다. 이 안의 목적함수는 이탈률이 아니라 검증 가능성이므로, 오히려 판정 로직 3단계(부양→소득→재산)에 화면을 대응시켜 나누는 쪽을 택한다. 이탈이 늘어도 감수한다. |
| 5 | "40~60대가 주 사용자"라는 연령 기반 타깃은 이 안과 무관하다. 이 안의 타깃은 나이가 아니라 역할(세무사·노무사 등 실무자, 꼼꼼히 대조하려는 당사자)로 정의된다. 연령을 근거로 글자 크기·정보 밀도를 낮추지 않고, 오히려 전문 용어·조항 번호를 그대로 노출하는 근거로 삼는다. |
| 7 | "판정이 계산보다 신뢰를 준다"는 전제는 확정형 어휘 자체가 신뢰의 원천이라고 본다. 이 안은 반대로 결론을 단정하지 않고 조건부·헤징으로 표현하며, 신뢰는 "확정형 어휘"가 아니라 "근거를 보여주는 행위"에서 나온다고 본다. 두 전제는 정면으로 충돌하므로 후자를 채택한다. |

## 2. 유입과 랜딩 가정

- 사용자가 이 서비스에 도달하는 경로: 일반적 판정 키워드("피부양자 자격 확인")보다, 특정 조항·기준값을 확인하려는 롱테일 검색("피부양자 재산과세표준 5.4억 근거", "국민건강보험법 시행령 제41조")을 통해 개별 근거 페이지/판정 결과 화면에 직접 랜딩한다고 가정한다. 재방문·북마크(레퍼런스로 저장해두고 매년 다시 찾아옴) 비중이 상대적으로 크다고 가정한다.
- 첫 화면으로 가정하는 페이지: 홈이 아니라 판정 결과 화면 또는 근거 조항이 노출된 개별 페이지. 검색엔진이 도구 내부의 특정 조항 설명 지점으로 직접 진입시킨다고 본다.
- 이 가정이 틀리면 무너지는 부분: 실제 유입 대부분이 홈을 거쳐 "빠른 결론"만 원하는 일반 사용자라면, 근거·계산 과정을 앞세우는 이 구조는 불필요한 진입장벽이 되어 이탈만 유발하고 이 안의 존재 이유가 사라진다.

## 3. 홈 구조

랜딩을 홈이 아니라 개별 판정/근거 페이지로 가정했으므로, 홈은 온보딩·설득의 자리가 아니라 "조항 색인"으로 축소한다. 홈에는 도구 목록과 함께, 그 도구들이 참조하는 법령·고시 조항을 조항 번호 순으로 나열한 인덱스를 둔다(예: "국민건강보험법 시행령 제41조 → 피부양자 재산요건 판정에서 사용"). 마케팅적 설득 문구, 사용 사례 소개, CTA 강조는 두지 않는다. 이유: 이미 검색을 통해 구체적 목적을 갖고 들어온 사용자에게는 조항 위치를 빠르게 찾게 해주는 것이 설득보다 우선한다.

## 4. 입력 화면 구조

- 화면 분할 방식: 피부양자 판정기 1개로 범위를 좁히고, 그 안에서 `judge.ts`의 3단 로직(부양요건 → 소득요건 → 재산요건)에 화면을 그대로 대응시켜 카드 3개로 분리한다. 사용자가 입력을 진행하면서 "지금 어떤 조항을 검토 중인지"를 알 수 있게 한다.
- 입력 항목 수: 기존과 동일한 11개 필드를 유지하되, 배치를 부양요건(4) / 소득요건(6, 5종 소득 + 사업자등록) / 재산요건(1)로 나눈다. 필드 수 자체를 줄이거나 늘리는 것은 이 안의 관심사가 아니다(그것은 축1 하위결정이며 이미 T0/좁음으로 정리됨).
- 각 항목의 설명 노출 방식: 모든 필드 옆에 근거 조항 번호·기준값의 출처·시행일을 접지 않고 상시 노출한다(힌트 텍스트가 아니라 별도의 각주형 마진노트). 예: "형제자매는 소득요건 외 동거 요건 추가 적용 — 국민건강보험법 시행규칙 별표1의2 제3호". "펼쳐야 보이는" 정보로 두지 않는다 — 이것이 이 안의 핵심이므로 기본 숨김은 채택하지 않는다.

## 5. 결과 화면 구조

- 정보 제시 순서: 결론을 맨 위에 두지 않는다. 입력값 요약 → 적용된 조항·기준값 표 → 단계별 판정 진행(부양요건 충족 여부 → 소득요건 → 재산요건, 각 단계마다 사용된 값과 조항을 병기) → 맨 마지막에 최종 결론. 계산 과정을 다 보여준 뒤에 결론이 나오는 순서.
- 결론 표현의 강도와 정확한 문구 예시: 확정형("인정됩니다", "탈락합니다")을 쓰지 않는다. "제출하신 조건과 2026년 기준 재산과세표준 5.4억원 문턱값(국민건강보험법 시행령 제41조)을 적용하면, 재산요건은 충족하는 것으로 계산됩니다.", "위 세 요건을 모두 적용한 결과, 피부양자 자격 요건을 충족하는 것으로 판단됩니다(본 계산은 참고용이며, 최종 판정은 국민건강보험공단 심사에 따릅니다)." "~로 계산됩니다" / "~로 판단됩니다" 형태를 일관되게 쓴다.
- 다음 행동 제시 방식: 전환 유도형 CTA(다른 도구로 이동, 공유하기)를 주 동선에 놓지 않는다. 대신 "근거 조항 원문 보기"(법제처 링크), "계산 과정 전체 펼쳐보기", "이 결과 인쇄/PDF 저장"을 제공한다. 다른 도구로의 이동 링크는 존재하되 최하단에 부차적으로만 배치한다.

## 6. 시각 체계

- 색상:
  - 배경(본문 프로즈): `#FFFFFF`
  - 배경(근거/각주 패널, 본문과 구역 구분용): `#EEF2F6`
  - 기본 텍스트: `#171717`
  - 보조 설명 텍스트: `#3F3F46`
  - 근거 마커/조항 링크 전용 색(성공·실패 색과 완전히 분리): `#1E3A5F`
  - 검증 상태 "대조 완료" 표시: `#0F5132` (텍스트만, 배지 배경 없음)
  - 검증 상태 "미검증" 표시: `#7A5B00` (텍스트만, 배지 배경 없음)
  - 판정 결론 텍스트: 별도 색상 없이 기본 텍스트 색(`#171717`)과 동일 — 색으로 확신을 표현하지 않음
  - 표/블록 테두리: `#D4D4D8` (1px solid, 그림자 없음)
- 타이포 스케일:
  - 본문 프로즈(설명문): 16px / line-height 1.7, sans-serif
  - 인용 법령 원문·조건문: 15px, monospace, 좌측 세로선으로 구분
  - 계산식·수치 표: 14px, monospace, tabular-nums, 우측 정렬
  - 각주/출처 표기: 13px, sans-serif
  - h1: 22px / 섹션 헤더(예: "1단계: 부양요건"): 18px, 번호 매김
- 간격 스케일, 콘텐츠 최대폭:
  - 간격: 4px 배수 그리드(4/8/12/16/24/32)
  - 콘텐츠 최대폭: 데스크톱 1040px (본문 640px + 마진노트 320px + gap 80px 2단 구성), 모바일은 마진노트가 본문 하단에 접힌 각주로 전환되어 앵커 클릭 시 펼쳐짐

## 7. 갱신 부담

- 기준이 바뀌면 수정해야 하는 지점: 기존 갱신 표면(상수 파일 2개, 가이드 하드코딩 34건, 도구 문구 7개 파일)에 더해, 이 안은 상수마다 근거 조항 번호·시행일·검증 상태(VERIFIED_AGAINST_NHIS류 플래그)를 메타데이터로 함께 유지해야 한다. 즉 `number` 하나였던 상수를 `{ value, statute, effectiveDate, verified }` 구조로 확장해야 하고, 이 구조를 렌더링하는 마진노트 컴포넌트도 매년 조항 번호·시행일이 그대로인지 재확인해야 한다.
- 연 1회 갱신 시 예상 작업량: 기존 대비 1.5~2배. 값 자체를 바꾸는 작업은 기존과 동일하지만, 조항 번호·시행일 표기의 정확성까지 매년 재검증해야 하므로(틀린 조항 번호를 노출하면 "추적 가능성"이라는 이 안의 핵심 약속이 깨짐) 검증 공수가 새로 추가된다.

## 8. 포기한 것

| 포기한 가치 | 왜 포기해도 되는가 |
|---|---|
| 빠른 완결(전환 속도) | 이 안의 목적함수는 검증 가능성이지 속도가 아니다. 법령 원문·계산 과정을 다 보여주는 구조는 필연적으로 결론까지 도달하는 시간을 늘린다. 빠른 결론이 목적이라면 애초에 이 안을 택하지 않는다. |
| 일반인 접근성·친절함 | 조항 번호·전문 용어를 그대로 노출하면 비전문가에게는 위압적으로 보인다. 이 안은 "쉬운 설명"보다 "정확한 출처"를 우선하며, 일반 사용자의 체감 난이도가 올라가는 것을 감수한다. |
| 확장성 있는 허브 정체성 | 스코프를 피부양자 판정 1개로 좁게 유지하므로(축1: 좁음), 4개 영역을 아우르는 내비게이션·정보구조 확장은 이번 안의 관심사가 아니다. 이는 다른 목적함수(허브화)에 속하는 문제다. |
| 단정적 결론이 주는 안심감 | 헤징 표현("~로 계산됩니다")을 쓰므로 사용자는 "이제 다 끝났다"는 확신을 얻지 못하고, 최종적으로는 스스로(또는 공단을 통해) 재확인해야 한다는 부담이 남는다. |
| 시각적 화려함·브랜드 각인력 | 표·각주·monospace 중심의 문서형 레이아웃은 마케팅적으로 기억에 남는 브랜드 톤보다 딱딱하고 재미없어 보일 위험을 감수한다. |

## 9. 이 안이 실패하는 조건

- 실제 이벤트/설문 데이터로 확인했을 때 사용자 대다수가 결론만 원하는 일반인이고, 실무자·검증 목적 사용자 비중이 무시할 만큼 작다는 사실이 밝혀지면, 이 안이 최적화하는 목적함수 자체가 틀린 타깃을 향한 것이므로 폐기해야 한다.
- 조항 번호·시행일 병기 작업이 실제로는 충분히 검증되지 않은 채 배포되어(예: 조항 번호 오기재, 개정 반영 누락) "추적 가능성"이라는 핵심 약속을 지키지 못하는 사례가 발견되면, 이 안은 오히려 잘못된 근거를 신뢰하게 만드는 역효과를 내므로 폐기하거나 근거 표기 방식을 근본적으로 재설계해야 한다.
- 모바일 사용자 비중이 절대적으로 크고(Brief상 기존 앱이 breakpoint sm 위주로만 구현된 점은 모바일 중심 사용 가능성을 시사한다), 접힌 각주 방식이 실측상 근거 접근률을 오히려 낮춘다는 것이 확인되면, 2단 마진노트 구조를 재설계해야 한다.

### 폐기·수정할 요소

- 조항 검색 유입을 핵심 전제로 삼으려면 조항·질문별 정적 가이드 URL이 실제로 필요하다. 만들지 않는다면 유입 전제를 `일반 판정 검색 후 근거 확인`으로 변경한다.
- 법령집처럼 보이게 만들어 원문 권위를 차용하지 않는다. 민간 서비스 브랜드와 해설·원문 인용의 경계를 명확히 표시한다.
- 데스크톱 2단 마진노트를 기본 구조로 고정하지 않는다. 모바일에서는 결과 직후 펼쳐진 근거 요약과 선택적 상세 원문 링크가 더 적합하다.
- PDF 저장은 브라우저 인쇄 기능으로만 제공하거나, 서버·외부 API를 사용한다면 개인정보처리방침과 전송 동의를 먼저 변경한다.

신뢰는 딱딱한 문서형 외관이 아니라 **검증 가능한 데이터와 갱신 절차**에서 만들어야 한다.
