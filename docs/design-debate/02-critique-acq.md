# 유입 비평 — 방향 A / B / C 판정 결과

## 방향 A 유입 판정

**종합: 조건부**

### 유입 가정
- 제안서가 명시한 가정: 사용자는 "피부양자 자격 조건" 등 구체적 판정 검색어로 판정 도구 페이지(`/health-insurance/dependent/`)에 직접 랜딩한다. 홈이 아니라 도구 페이지가 사실상의 랜딩이라고 명시적으로 밝히고, 이 가정이 틀릴 경우(2단계 여정 다수, 브랜드 검색 유입)를 스스로 실패 조건으로 적시했다.
- 명시되지 않은 부분: 도구 페이지 자체(입력 화면)에 서비스 정체성·신뢰 요소(운영 주체, 데이터 근거, 로고/헤더)가 존재하는지 언급이 없다. 3절은 "홈이 헤드라인·CTA를 갖는다"고만 서술하고, 홈을 거치지 않고 도구에 바로 떨어진 사용자가 이 서비스가 무엇인지 어떻게 알게 되는지는 4절 어디에도 없다. 즉 스스로 세운 "판정 도구 페이지가 랜딩"이라는 전제를 도구 페이지 설계 자체에는 반영하지 않았다.

### 시나리오별 평가
| 시나리오 | 성립 여부 | 무너지는 지점 |
|---|---|---|
| 검색 직접 진입 | 부분 성립 | 결론 도달 속도(목적함수)는 설계상 잘 최적화되어 있으나, 서비스 정체성·운영 주체·"이게 믿을 만한가"에 대한 신호가 도구 페이지 어디에도 설계되지 않음. 홈에만 있는 헤드라인·설명 1문장이 실제로는 대부분의 방문자에게 도달하지 않는데도 그 문장이 서비스 소개 역할을 유일하게 맡고 있음 |
| 홈 경유 | 성립 | 홈이 이미 "도구로 가는 스플래시"로 최소화되어 있어 단일 CTA가 명확한 첫 행동을 만든다. 다만 재방문자가 가이드나 다른 정보를 찾으려 하면 홈에 그 경로가 없다(가이드 목록 의도적 배제) |
| 결과 공유 진입 | 취약 | 근거·계산 과정이 기본 접힘이고 입력값 요약도 상단에 없는 상태에서 "인정됩니다/탈락합니다" 솔리드 컬러 블록만 눈에 들어오는 구조다. 캡처·공유 시 어떤 조건을 근거로 나온 결론인지 맥락이 통째로 빠질 위험이 설계에서 고려되지 않았다 |

### 검색 표면
- 인덱싱 가능 페이지 수: 홈 1 + 판정기 1 + 가이드 6편 = 대략 8개. 지역보험료·임의계속가입은 이미 비공개이므로 검색 표면에서 제외된다.
- 정적 판정 페이지 존재 여부: 없음. 판정 조건별(재산 초과/소득 초과 등) 정적 결과 페이지는 설계되지 않았고, 결과는 클라이언트 입력 기반으로만 생성된다. "판정 관련 검색어로 도구 페이지에 랜딩"이라는 가정은 도구의 입력 화면 URL 자체에는 성립하지만, 세부 조건별 롱테일 검색어를 잡을 별도 표면은 없다.
- 브랜드 검색 도달 가능성: 제안서 스스로 "브랜드 검색('사대보험')으로 들어온 사용자에게 '이게 전부인가'라는 인상을 줄 수 있다"고 인정했고, 9절 실패조건에도 이 리스크가 반영되지 않은 채 방치되어 있다.

### 노력 배분 낭비
- 홈에 배정된 설계 자체가 이미 최소(헤드라인 1줄 + CTA + 1문장)이므로, 시나리오 1에서 "낭비"라 할 만한 여분의 설계가 거의 없다. 이 안은 홈 투자를 의도적으로 억제했다는 점에서 세 안 중 노력 배분 자체는 가장 목적함수에 부합한다. 다만 그 대가로 "홈에서만 전달되던 신뢰·정체성 정보"가 도구 페이지 쪽으로 이관되지 않고 통째로 증발했다.

### 결정적 결함
도구 페이지 단독 진입을 랜딩의 기본값으로 못 박았음에도, 정작 도구 페이지 설계(4~5절)에는 서비스 정체성·신뢰 신호가 전혀 명시되지 않았다. 검색 직접 진입 사용자가 "이 결과를 왜 믿어야 하는가"를 판단할 근거가 홈에만 있고 홈은 대부분 보지 않는다는 이 안 자신의 가정과 정면으로 충돌한다.

## 방향 B 유입 판정

**종합: 조건부**

### 유입 가정
- 제안서가 명시한 가정: 다수 사용자가 개별 도구/가이드 페이지로 먼저 진입하되, 이 안이 겨냥하는 대상은 "질문 하나로 끝나지 않는다"는 것을 알아차리는 재방문·연쇄 탐색 사용자다. 홈이 최초 랜딩일 확률은 낮다고 스스로 명시하며, 대신 모든 페이지에 상시 헤더 내비게이션과 결과 하단 교차링크를 둬 "어느 페이지로 들어와도 허브에 접속"되도록 설계했다.
- 명시되지 않은 부분: "재방문·교차 탐색이 실제로 다수인가"에 대한 근거는 전혀 제시되지 않고 가정으로만 남아 있다(9절에서 스스로 이 점을 실패조건으로 인정). 또한 헤더 내비게이션이 시나리오 1에서 구체적으로 어떤 정보량(도메인 3개 노출인지, 접힌 메뉴인지)으로 나타나는지 6절 시각 체계에 명시되지 않았다.

### 시나리오별 평가
| 시나리오 | 성립 여부 | 무너지는 지점 |
|---|---|---|
| 검색 직접 진입 | 부분 성립 | 상시 헤더 내비게이션 덕분에 "이게 허브의 일부"라는 정체성은 다른 두 안보다 잘 전달된다. 다만 홈에 배정된 설계 분량의 대부분(상황 라우터, 3도메인 카드 그리드, 빌드상태 배지 체계)은 도구 페이지에는 나타나지 않는 순수 홈 전용 자산이라, 이 안이 스스로 "홈이 랜딩일 확률이 낮다"고 인정한 것과 투자 배분이 어긋난다 |
| 홈 경유 | 성립 | 상황 기반 라우터와 도메인 섹션이 뚜렷한 첫 행동을 만든다. 다만 국민연금·고용보험 섹션이 전부 "준비 중" 비활성 카드인데, 로드맵 착수 시점이 미정임을 9절이 스스로 인정하고 있어 재방문자에게 "미완성 서비스"라는 인상을 줄 위험이 있다 |
| 결과 공유 진입 | 성립 | 조건부 헤징 문구("현재 입력 기준으로는")와 3단계 체크리스트가 맥락 없이 봐도 오해를 줄인다. 다만 결과 하단의 "관련해서 더 확인할 것" 카드가 비공개 상태인 지역보험료 계산기 등을 "검증 중" 배지로 노출하는데, 공유받은 사람이 클릭했다가 미완성 기능을 마주치면 서비스 신뢰도에 대한 인상이 나빠질 수 있다 |

### 검색 표면
- 인덱싱 가능 페이지 수: 홈 1 + 판정기 1(건강보험) + 가이드 6편 = 실질 콘텐츠 페이지 수는 A와 동일한 약 8개. 국민연금·고용보험 도메인은 "준비 중" UI 상태일 뿐 실제 콘텐츠가 없어 검색 표면에 기여하지 않는다.
- 정적 판정 페이지 존재 여부: A와 동일하게 없음. 조건별 정적 결과 페이지는 설계되지 않았다.
- 브랜드 검색 도달 가능성: 제안서 내 별도 언급 없음. 허브형 정체성("여러 사대보험 결정을 한 곳에서")은 브랜드 자체보다 카테고리 설명에 가까워, 브랜드 검색으로 도달하려는 재방문자에게 서비스명을 상기시키는 장치가 설계에 없다.

### 노력 배분 낭비
- 홈 설계 분량이 세 안 중 가장 크다(상황 라우터 3~4개, 3도메인 색상·배지 체계, 카드 그리드, 가이드 목록). 그런데 제안서 스스로 "실제 최초 랜딩은 개별 도구/가이드 페이지일 확률이 더 높다"고 명시했다. 이 대형 홈 자산 중 시나리오 1에서 살아남는 것은 헤더 내비게이션(얇은 바) 정도뿐이며, 상황 라우터·도메인 카드 그리드·빌드상태 배지 시스템 전체는 시나리오 1 사용자에게 도달하지 않는다. 홈 설계 분량 대비 생존 비율이 세 안 중 가장 낮다.

### 결정적 결함
없음. 다만 홈 투자 규모와 "홈이 랜딩일 확률이 낮다"는 자체 가정 사이의 불균형이 커서, 재방문·교차 탐색 비중이 실측으로 낮게 나올 경우(9절이 이미 자인한 실패조건) 이 안의 핵심 자산 대부분이 무효화되는 구조적 취약성을 안고 있다.

## 방향 C 유입 판정

**종합: 취약**

### 유입 가정
- 제안서가 명시한 가정: 일반적 판정 키워드보다 "피부양자 재산과세표준 5.4억 근거", "국민건강보험법 시행령 제41조" 같은 롱테일 조항 검색을 통해 "개별 근거 페이지/판정 결과 화면"에 직접 랜딩하며, 재방문·북마크(레퍼런스 저장) 비중이 크다고 가정한다. 홈은 온보딩이 아니라 "조항 색인"으로 축소된다.
- 명시되지 않은 부분: "판정 결과 화면"이 개인화된 11개 필드 입력에 의존하는 클라이언트 상태 산출물이라는 점과, 검색엔진이 "특정 조항 설명 지점으로 직접 진입"시킨다는 가정이 어떻게 기술적으로 양립하는지가 설명되지 않는다. 3~5절 어디에도 조항별로 별도 URL을 가진 정적 페이지를 만들겠다는 설계가 없다 — 근거·조항 정보는 결과 화면 안의 마진노트(각주)로만 존재한다. 즉 이 안이 유입 경로로 지목한 롱테일 조항 검색이 실제로 도달할 인덱싱 가능한 목적지가 설계에 없다.

### 시나리오별 평가
| 시나리오 | 성립 여부 | 무너지는 지점 |
|---|---|---|
| 검색 직접 진입 | 취약 | 이 안이 가정한 "조항 검색 → 근거 페이지 직접 랜딩"이 성립하려면 조항별 정적 페이지가 있어야 하는데, 실제 설계(4~5절)는 근거를 판정 도구의 입력·결과 화면 안 마진노트로만 배치한다. 즉 검색엔진이 색인할 만한 조항 단위 랜딩 지점 자체가 구조적으로 존재하지 않는다. 홈의 "조항 색인"이 유일한 조항 관련 인덱싱 자산이나, 이는 홈 1페이지에 조항 목록이 나열되는 것이지 조항별 개별 URL이 아니다 |
| 홈 경유 | 부분 성립 | 조항 색인은 목적을 가진 재방문자(실무자)에게는 기능하지만, 첫 행동(CTA)이 의도적으로 배제되어 일반 재방문자에게는 "무엇을 눌러야 하는지" 모호하다. 도구 목록이 병기된다고는 하나 마케팅적 설득이나 강조가 없어 저동기 방문자를 이탈시킬 수 있다 |
| 결과 공유 진입 | 성립 | 입력값 요약을 결과 최상단에 두고, 헤징 문구("~로 계산됩니다")와 참고용 고지를 명시하는 구조는 세 안 중 맥락 손실에 가장 강하다. 캡처·공유되어도 무엇을 근거로 나온 결론인지 스스로 설명하는 설계다 |

### 검색 표면
- 인덱싱 가능 페이지 수: 홈(조항 색인) 1 + 판정기 1. 가이드 페이지의 존속 여부가 이 제안서에 언급되지 않아 A·B와 달리 확인 불가 — 이 자체가 검색 표면을 스스로 판단하기 어렵게 만드는 결함이다.
- 정적 판정 페이지 존재 여부: 없음. 조항별·조건별 정적 페이지가 설계되지 않았으며, 이는 이 안이 내세운 유입 가정(롱테일 조항 검색)과 정면으로 모순된다. 조항 색인이 존재하긴 하나 이는 색인 페이지 1개일 뿐, 검색엔진이 개별 조항 질의로 도달할 개별 URL이 아니다.
- 브랜드 검색 도달 가능성: 제안서에 별도 언급 없음. 레퍼런스형 포지셔닝(정확성·추적가능성)은 브랜드 자체보다 신뢰 속성을 내세우므로, 브랜드명을 기억해 재검색하도록 유도하는 장치가 설계에 없다.

### 노력 배분 낭비
- 홈 설계 자체는 최소(조항 색인)라 절대적 투입량은 작다. 그러나 이 안의 핵심 설계 노력은 근거·각주·2단 마진노트·검증 상태 배지 등 결과/입력 화면에 집중되어 있고, 이는 시나리오 1에서도 살아남는다. 노력 배분의 "낭비"는 홈이 아니라 유입 가정 자체의 실현 불가능성(아래 결정적 결함)에 있다.

### 결정적 결함
이 안이 2절에서 명시한 핵심 유입 가정 — "롱테일 조항 검색을 통해 개별 근거 페이지에 직접 랜딩" — 을 뒷받침할 정적·인덱싱 가능한 조항별 페이지가 3~5절 어디에도 설계되어 있지 않다. 근거 정보는 판정 도구의 마진노트로만 존재하므로, 검색엔진이 실제로 이 안이 가정한 경로로 사용자를 데려올 목적지가 구조적으로 없다. 가장 가능성 높다고 자인한 시나리오(검색 직접 진입, 그것도 일반 판정어가 아닌 조항 특정 검색)에서 이 안의 존재 근거 자체가 성립하지 않는다.

## [codex 피드백]

이 비평의 시나리오 분석은 유용하지만, 이후 경쟁 재조사를 반영해 검색시장 전제를 보완해야 한다.

### 추가 관찰

- `피부양자 자격 계산기`, `피부양자 판정기`, `피부양자 가능 여부 확인` 같은 도구 의도 검색에서는 실제 민간 판정기가 검색된다.
- 반면 `피부양자 자격`, `부모님 피부양자 조건` 같은 일반 정보 검색은 법령·공단·금융사·블로그 비중이 높다.
- 따라서 기회는 `도구가 전혀 검색되지 않음`이 아니라 `정보형 검색에서 신뢰도 높은 도구로 연결되는 대표 경로가 약함`으로 정의한다.

### 평가 방식 수정

- 검색엔진, 검색어, 날짜, 상위 몇 개 결과를 확인했는지 기록한다.
- 인덱싱 페이지 수보다 **검색 의도에 대응하는 유효 랜딩 페이지 수**를 비교한다.
- C안도 공통 런치 범위의 가이드 6편을 삭제한다고 명시하지 않았으므로 검색 표면을 홈+판정기 2개로 단정하지 않는다. 대신 조항별 랜딩 페이지가 0개라는 문제를 지적한다.
- B안의 홈 투자를 `낭비`라고 판정하려면 예상 구현비용과 직접 랜딩에서 재사용되는 자산을 구분한다.
- 검색 유입만 평가하지 말고 공식 링크 유입, 결과 공유, 재방문, 직접 방문을 측정할 이벤트와 성공 기준도 제안한다.

권장 유입 구조는 `질문별 정적 가이드 → 하나의 검증된 판정기 → 공식 확인 경로`다.
