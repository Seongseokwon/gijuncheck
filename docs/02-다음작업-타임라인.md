## 이 문서의 역할

초기 개발 일정이 아니라, 공개 서비스가 운영되고 있는 현재 시점부터의 실행 순서를
관리한다. 기능을 추가할 때는 검색량 추정만으로 결정하지 않고 다음 순서를 따른다.

> 공식 근거 확인 → 코드·화면 반영 → 대표 사례 테스트 → 검증기록 갱신 → 공개 →
> 검색·사용 데이터 관찰

11월은 피부양자·퇴직 후 건강보험 관련 검색 수요가 커질 수 있는 운영 목표점으로 둔다.
정확한 트래픽 규모나 검색 피크는 Search Console·GA4 데이터로 확인하기 전까지 가정으로
취급한다.

## 지금부터의 우선순위

### 1순위 — 공개 서비스 운영 안정화

**목표:** 검색엔진과 실제 이용자가 최종 도메인에서 끊김 없이 핵심 흐름을 완료하는지
확인한다.

- [x] 최신 배포본에서 `https://gijuncheck.kr/`, `/robots.txt`, `/sitemap.xml`,
      `/verification-policy/`와 세 도구 URL의 응답 상태 확인
- [x] 임시 Vercel 주소가 최종 도메인으로 리다이렉트되고, 최종 도메인이 canonical·`og:url`·
      sitemap에 일관되게 사용되는지 확인
- [x] 모바일에서 홈 → 피부양자 판정 → 지역보험료 → 임의계속가입 이동을 직접 점검
- [x] 결과 화면의 출처 링크, 체크리스트, 공단 문의 질문, 면책 문구가 모두 노출되는지 점검

2026-08-03 사용자 확인: 최신 배포본을 실제 iPhone Safari에서 확인했고, 세 도구의
신뢰 신호·결과 안내·출처·체크리스트·면책 문구와 모바일 좌우 여백을 정상 확인했다.
- [x] 배포 전후 `npm test`, `npm run build`, 핵심 E2E를 실행하고 결과를 기록

**완료 기준:** 최종 도메인에서 핵심 URL·리다이렉트·메타데이터·모바일 메뉴·3개 도구
동선이 모두 정상이며, 공식 확인이 필요한 부분이 화면에 명시된다.

### 2순위 — 색인·분석 운영 루틴

**목표:** 색인 여부와 실제 유입·완료 흐름을 숫자로 확인한다.

- [ ] 색인 요청 후 1주 단위로 Google Search Console의 색인·제외·canonical 선택 결과 확인
- [ ] 네이버 서치어드바이저 수집·색인 상태를 같은 주기로 확인
- [ ] GA4에서 `도구 진입 → 판정 시작 → 판정 완료 → 공식 출처 클릭 → 다음 도구 이동` 흐름을
      확인할 수 있도록 필요한 이벤트만 점검
- [ ] 내부 테스트 트래픽을 구분하거나 제외하는 방법을 정하고, 개인 입력값이 전송되지 않는지
      재검증
- [x] Vercel Speed Insights를 연결한다. — `@vercel/speed-insights`를 공통 레이아웃에 추가하고 배포 완료
- [ ] Vercel Speed Insights에서 실제 데이터가 누적되는지 확인하고 GA4와 역할을 분리한다.

**완료 기준:** 색인 상태, 유입 검색어, 판정 완료율, 공식 출처 클릭, 모바일 성능을 월간
운영표에서 확인할 수 있다.

### 3순위 — 가이드 6편 품질·내부 링크 보강

**목표:** 검색으로 바로 들어온 이용자도 최신 기준과 다음 행동을 이해하게 한다.

가이드마다 아래 항목을 점검한다.

- [x] 기준연도와 최종 확인일이 표시되는가
- [x] 법령·국민건강보험공단·공공기관 원문 링크가 실제로 열리는가
- [x] 계산기 또는 피부양자 판정기로 이어지는 내부 링크가 있는가
- [x] 피부양자·지역보험료·임의계속가입 중 관련 도구가 연결되는가
- [x] FAQ·구조화 데이터가 화면에 실제 표시되는 내용과 일치하는가
- [x] 제도상 확정 사실과 기준체크의 참고 설명이 구분되는가
- [x] 오래된 90일, 과거 요율, 검증되지 않은 단정 표현이 남아 있지 않은가

2026-08-03 점검 결과: 6편의 기준연도·최종 확인일·FAQ·구조화 데이터·내부 도구 연결을
확인했고, 접속 불안정하거나 현재 안내와 충돌할 수 있는 민간 보조 출처 5개를 제거했다.
공식 출처 링크가 최소 1개 이상 존재하는 조건을 `e2e/guide-quality.spec.ts`에 추가했다.

**완료 기준:** 6편 모두 출처·최신성·내부 링크·한계 설명을 통과하고, 각 글에서 최소
하나의 관련 도구로 이동할 수 있다.

### 4순위 — 신뢰 신호의 화면 개선

**목표:** 검색 유입자가 홈이나 검증 원칙 페이지를 거치지 않아도 결과의 신뢰 범위를
즉시 이해하게 한다.

- [x] 각 도구 상단에 기준연도, 최종 검토일, 검증 상태를 짧게 표시
- [x] 지역보험료는 “공단 모의계산 대표 13건 대조” 범위를 명시
- [x] 임의계속가입은 “법령·공단 산식 기반 참고 비교”이며 개별 고지액 복제가 아님을 표시
- [x] 피부양자 판정은 공개 기준 대조와 공단 실제 처리 결과 대조를 구분
- [x] 결과 화면의 “확인할 자료”와 “공단에 물어볼 질문”을 첫 화면에서 찾기 쉽게 배치

2026-08-03 반영: 공통 `TrustSignal`을 세 도구 상단에 추가하고, 피부양자 결과 상단에
확인 자료·공단 문의 질문 체크리스트로 이동하는 링크를 추가했다. 기준연도·최종 확인일·
검증 범위 문구는 `e2e/pages.spec.ts`에서 회귀 검사한다.

**완료 기준:** 이용자가 결과를 공식 결정으로 오해하지 않으면서도, 무엇을 확인하고
공단에 어떤 질문을 해야 하는지 바로 알 수 있다.

## 수익화는 운영 기준선 이후

애드센스는 기능 공개보다 먼저 진행하지 않는다.

### 신청 전 조건

- [ ] 주요 가이드가 색인되고 최신 출처·최종 확인일을 갖춘다.
- [ ] 개인정보처리방침·이용약관·문의 페이지가 실제 운영 방식과 일치한다.
- [ ] 광고·쿠키 사용 여부를 정책 문서에 반영한다.
- [ ] 광고가 입력 폼, 결과 핵심 문장, 모바일 CTA를 방해하지 않는 배치안을 만든다.

### 승인 후 원칙

- [ ] 가이드 본문과 결과 이후에만 제한적으로 배치
- [ ] 모바일 CLS와 판정 완료율을 광고 전후 비교
- [ ] 수익보다 이탈률·사용성·신뢰 훼손 여부를 우선 확인

## 안전 규칙

1. `ready: false` 기능은 공식 대조가 끝나기 전까지 메뉴·홈·sitemap에 공개하지 않는다.
2. 지역보험료와 임의계속가입의 계산 결과를 공단의 개별 고지액·심사 결과로 표현하지 않는다.
3. 공단 공식 기준, 직접 대조 결과, 기준체크의 참고 계산을 화면과 문서에서 구분한다.
4. 분석 이벤트에 소득·재산·관계 등 개인을 추정할 수 있는 원본 입력값을 넣지 않는다.
5. 제도 변경 시 숫자만 수정하지 말고 출처·테스트·설명·검증기록을 함께 갱신한다.
6. 검증되지 않은 경쟁 우위, 검색량, 수익 전망을 사실처럼 문서화하지 않는다.
