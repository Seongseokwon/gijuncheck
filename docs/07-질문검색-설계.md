# 질문 검색 설계 (P3)

작성일: 2026-08-03
관련 문서: [QA 전수점검](./06-QA-전수점검.md) · [상세기획서](./01-상세기획서.md) · `docs/04-실행-우선순위.md`(로컬 전용)

---

## 1. 이 문서의 결론

우측 하단 고정 챗봇 대신, **사이트가 이미 갖고 있는 답을 질문으로 찾아가게 하는 검색 위젯**을
만든다. 서버도 LLM도 쓰지 않는다. 정적 사이트 그대로, 클라이언트 순수 함수로 동작한다.

| 항목 | 결정 |
| --- | --- |
| 배치 | 홈 히어로 아래 + 가이드·도구 페이지 하단 인라인 |
| 인덱스 범위 | 가이드 6편(FAQ·목차·리드) + 도구 3개 + 2026년 판정 기준값 |
| 답변 생성 | 하지 않는다. 기존 문장으로 **이동**만 시킨다 |
| 검색어 수집 | 하지 않는다. 개인정보처리방침 개정 불필요 |
| 서버 | 없음. `output: 'export'` 유지 |

### 이 설계가 지키는 기존 제약

- **규칙 1(숫자를 코드에 직접 쓰지 않는다)** — 기준값 항목은 `constants/2026.ts`에서 파생한다.
- **규칙 2(로직을 UI에 넣지 않는다)** — 매칭 엔진은 React를 import하지 않는 순수 함수다.
- **규칙 3(경로는 routes.ts에만 쓴다)** — 인덱스의 링크는 `RouteKey`로만 지정한다.
- **규칙 4(결과에는 근거와 기준 연도를 붙인다)** — 검색은 근거가 붙은 원문으로 보낼 뿐,
  요약·재서술하지 않는다.
- **개인정보처리방침** — 자유 입력값을 서버로 보내지 않는다는 문장이 그대로 유지된다.

## 2. 하지 않는 것

명시해두지 않으면 나중에 슬금슬금 들어온다.

1. **LLM 답변 생성.** 근거 없는 단정이 이 서비스의 유일한 차별점을 무너뜨린다.
2. **서버 엔드포인트.** 검색은 전부 브라우저에서 끝난다.
3. **`/search?q=` 결과 페이지.** 정적 내보내기에서 쿼리 파라미터 페이지는 SSG되지 않고,
   색인에 들어가면 저품질 URL이 양산된다. 검색은 위젯 안에서만 존재한다.
4. **우측 하단 고정 버블.** 모바일에서 CTA와 증빙 체크리스트를 가린다.
5. **검색어 원문 전송.** 사용자가 금액·이름을 적어 넣을 수 있는 자유 입력값이다.

## 3. 데이터 모델

```ts
// src/lib/search/types.ts

export type EntryKind = 'tool' | 'term' | 'faq' | 'section' | 'guide';

export interface SearchEntry {
  /** 안정적인 식별자. 이벤트·테스트에서 참조한다 */
  id: string;
  kind: EntryKind;
  /** 목록에 보이는 제목. 질문 원문 또는 섹션명 */
  title: string;
  /** 매칭 대상 본문. 목록에는 2줄로 잘라 보여준다 */
  body: string;
  /** 링크 대상 페이지 */
  routeKey: RouteKey;
  /** 페이지 안 앵커. 없으면 페이지 최상단 */
  anchor?: string;
  /** 구어체·동의어 보강. 본문에 없는 표현을 여기에 넣는다 */
  keywords?: readonly string[];
}
```

`href`는 저장하지 않고 `ROUTES[routeKey].path + (anchor ? '#' + anchor : '')`로 만든다.
경로 문자열이 인덱스에 복제되면 규칙 3이 깨진다.

## 4. 인덱스는 어디서 오는가

### 4.1 핵심 판단 — 인덱스를 손으로 쓰지 않는다

가이드 6편은 이미 `TITLE` · `LEAD` · `ANSWER` · `TOC` · `FAQ`를 모듈 상수로 갖고 있다
(예: `guides/pension-impact/page.tsx`). 검색용 문장을 따로 쓰면 본문과 인덱스가 갈라지고,
매년 기준이 바뀔 때 갱신 지점이 두 배가 된다. 1인 운영에서 이건 곧 방치를 의미한다.

### 4.2 콘텐츠를 `content.ts`로 분리한다

```
src/app/health-insurance/guides/pension-impact/
├── content.ts    ← TITLE·LEAD·ANSWER·TOC·FAQ·SOURCES (React 없음)
└── page.tsx      ← content.ts 를 import 해서 렌더 + metadata + JSON-LD
```

**분리가 필요한 이유는 두 가지다.**

1. 검색 엔진은 클라이언트에서 돈다. `page.tsx`를 import하면 페이지 컴포넌트 트리 전체가
   클라이언트 번들로 끌려 들어온다.
2. FAQ 답변은 `INCOME.TOTAL_LIMIT` 같은 상수를 템플릿 문자열로 품고 있다. 소스 텍스트를
   파싱하는 방식으로는 값이 풀리지 않는다. 모듈로 import해야 빌드 시점 값이 그대로 나온다.

`page.tsx`는 렌더만 남으므로 이 리팩터링에 기능 변화가 없고, 기존 E2E 246개가 회귀를 잡아준다.

```ts
// content.ts 계약
export interface GuideContent {
  routeKey: RouteKey;
  title: string;
  lead: string;
  answer: string;
  toc: readonly TocItem[];
  faq: readonly FaqItem[];
  /** 이 글을 찾을 때 사람들이 쓰는 말 */
  keywords?: readonly string[];
}
```

### 4.3 엔트리 생성 규칙

| 소스 | kind | title | body | anchor |
| --- | --- | --- | --- | --- |
| 가이드 1편 | `guide` | 글 제목 | `lead` + `answer` | 없음 |
| FAQ 항목 | `faq` | 질문 원문 | 답변 | `faq-1` … `faq-n` |
| 목차 항목 | `section` | 섹션명 + 글 제목 | 없음 | `TocItem.id` |
| 도구 3개 | `tool` | 도구명 | 한 줄 설명 | 없음 |
| 2026년 기준값 | `term` | 기준명 | 기준 문장 + 근거 | 도구 페이지 |

`term` 항목은 `constants/2026.ts`에서 파생한다. 숫자를 다시 적지 않는다.

```ts
// src/lib/search/terms.ts (발췌)
{
  id: 'term-income-limit',
  kind: 'term',
  title: '피부양자 합산소득 한도',
  body: `연 ${toManwon(INCOME.TOTAL_LIMIT)} 이하여야 합니다. 1원만 넘어도 탈락합니다.`,
  routeKey: 'dependent',
  keywords: ['2000만원', '소득 기준', '얼마까지'],
}
```

예상 규모: 가이드 6 + FAQ 24 + 섹션 24 + 도구 3 + 기준 8 = **약 65개**.
원문 기준 16KB 내외, gzip 6~7KB.

## 5. 매칭 엔진

`src/lib/search/engine.ts` — React를 import하지 않는 순수 함수. Fuse.js·lunr 같은 라이브러리를
넣지 않는다. 한국어 형태소 처리를 어차피 못 해주면서 번들만 키운다.

### 5.1 정규화

```
NFC 정규화 → 소문자 → 공백·구두점·콤마 제거
```

`2,000만원` / `2000 만원` / `2000만 원`이 같은 문자열이 된다.

### 5.2 유사도 — 문자 바이그램 Dice 계수

띄어쓰기가 무너지고("피부양자자격상실") 조사가 붙는("연금을") 한국어 입력에서
토큰 일치는 무력하다. 문자 2-gram 집합의 겹침 비율을 쓴다.

```
sim(A, B) = 2 · |bigrams(A) ∩ bigrams(B)| / (|bigrams(A)| + |bigrams(B)|)
```

- 질의가 1글자면 바이그램이 없다 → 부분문자열 매칭으로 대체
- 질의 문자열이 필드에 그대로 포함되면 `+0.35` 가산 (긴 문서가 손해 보는 것을 막는다)

### 5.3 필드 가중치

```
score = 1.00 · sim(query, title)
      + 0.55 · sim(query, body)
      + 0.85 · max(sim(query, keyword) for keyword in keywords)
```

- 임계값 `0.18` 미만은 버린다
- 상위 **6개**까지 노출
- 동점이면 `tool > term > faq > section > guide` 순 (행동으로 이어지는 것을 위로)
- **같은 페이지에서 최대 2개**만 남긴다. 한 글이 목록을 독점하면 검색이 무의미해진다

### 5.4 동의어 사전 — 이 기능의 실질적 성패

`src/lib/search/synonyms.ts`. 사용자는 법령 용어로 검색하지 않는다.
질의에 아래 키가 포함되면 확장어를 **가중치 0.9의 보조 질의**로 함께 채점한다.

| 사용자가 쓰는 말 | 확장 |
| --- | --- |
| 짤렸, 퇴사, 그만둠, 실직, 정년 | 퇴직, 자격상실 |
| 월급, 급여, 봉급 | 보수월액, 소득 |
| 집, 아파트, 집값, 재산세 | 재산, 과세표준 |
| 부모님, 아버지, 어머니, 시부모, 장인, 장모 | 직계존속 |
| 아들, 딸, 자식, 애 | 직계비속 |
| 형, 누나, 오빠, 언니, 동생 | 형제자매 |
| 얹혀, 밑으로 들어가, 올리다, 등록 | 피부양자 |
| 국민연금, 노령연금, 공무원연금 | 공적연금 |
| 알바, 프리랜서, 장사, 가게 | 사업소득, 사업자등록 |
| 얼마, 얼마나 | 보험료 계산 |
| 11월, 바뀐다, 올랐다 | 재산정 |

사전은 계속 자란다. 무결과 화면의 문의 메일이 유일한 입력 경로다(§9).

## 6. UI 설계

### 6.1 배치

| 위치 | 형태 |
| --- | --- |
| 홈 히어로 바로 아래 | 검색 입력 + **자주 찾는 질문 6개를 정적 링크로** 항상 노출 |
| 가이드·도구 페이지 하단 (`함께 읽기` 위) | "찾는 내용이 없나요?" 인라인 검색 |

홈의 자주 찾는 질문 6개는 서버 컴포넌트로 렌더한다. JS가 뜨기 전에도 보이고,
내부 링크가 늘어 색인에도 유리하다. 빈 검색창만 있는 화면은 중장년 사용자에게 벽이다.

### 6.2 상태

```
[초기]   입력창 + 자주 찾는 질문 6개
[입력중] 2글자 이상부터 150ms 디바운스 후 결과 목록 (최대 6개)
[결과]   제목(굵게) / 본문 2줄 / 출처 페이지명 배지
[무결과] 안내 + 도구 3개 링크 + 문의 메일 링크
```

예시 질문은 placeholder가 아니라 입력창 **아래 정적 텍스트**로 둔다.
placeholder는 대비가 낮고(`slate-500` = 4.01:1) 입력을 시작하면 사라진다.

### 6.3 접근성

`docs/archive/design-debate`의 대비 기준선과 `keyboard-a11y.spec.ts` 규약을 따른다.

- WAI-ARIA combobox 패턴: `role="combobox"` · `aria-expanded` · `aria-controls` ·
  `aria-autocomplete="list"` · `aria-activedescendant`
- 결과는 `role="listbox"` / `role="option"` + `aria-selected`
- 키보드: `↓`/`↑` 이동, `Enter` 이동, `Esc` 닫기, `Tab`은 자연 흐름 유지
- 결과 개수는 `aria-live="polite"`로 읽어준다 ("결과 3개")
- 옵션 최소 높이 **48px** (중장년·모바일 터치)
- 입력창은 기존 `inputCls`를 그대로 쓴다. 테두리 `slate-500`(4.01:1)은 이미 검증된 값이다
- 결과 목록은 `absolute`로 띄우되 모바일에서는 문서 흐름 안에 밀어 넣는다.
  떠 있는 목록이 하단 CTA를 가리는 것이 중장년 모바일에서 가장 흔한 실패다

### 6.4 앵커 딥링크

지금 `FaqSection`은 섹션 전체에 `id="faq"` 하나뿐이라 개별 질문으로 보낼 수 없다.

- `FaqSection`이 각 항목에 `id={`faq-${i + 1}`}` 부여
- 각 항목에 `scroll-mt-24` (헤더에 가리는 것 방지)
- `:target` 의사 클래스로 도착 지점을 강조 — CSS만으로 되므로 JS가 필요 없다
- 인덱스 앵커와 실제 DOM id의 일치는 E2E로 강제한다(§10)

## 7. 성능

검색 인덱스가 첫 화면 JS에 들어가면 홈 LCP를 해친다.

```ts
// QuestionSearch.tsx — 'use client'
const onFirstFocus = async () => {
  const { search } = await import('@/lib/search/engine'); // 인덱스는 여기에 딸려온다
  setEngine(() => search);
};
```

- 입력창에 처음 포커스(또는 첫 키 입력)할 때 동적 import
- 정적 내보내기에서도 코드 스플리팅은 정상 동작한다
- 초기 번들 증가분: 위젯 UI만 약 2KB. 인덱스 6~7KB는 지연 로드

## 8. 측정

`src/lib/analytics.ts`의 `EventMap`에 2개를 추가한다.
**number 필드는 넣지 않는다** — 이 파일의 경고 주석이 정한 규칙이다.

```ts
export interface QuestionSearchParams {
  has_result: boolean;
  surface: 'home' | 'guide' | 'tool';
}

export interface QuestionSearchSelectParams {
  /** 어디로 갔는가. RouteKey 는 사전 정의된 열거값이다 */
  route: RouteKey;
  kind: EntryKind;
  position: 'first' | 'other';
}
```

- `question_search`는 **검색 세션당 1회**만 보낸다 (마지막 입력 후 800ms 유휴)
- 검색어 원문은 어떤 형태로도 보내지 않는다
- 알 수 있는 것: 검색을 쓰는가 / 무결과 비율 / 어느 페이지로 가는가
- 알 수 없는 것: **무엇을 못 찾았는가**. 이 공백은 §9로 메운다

## 9. 커버리지 현실과 무결과 처리

FAQ 24개 + 기준 8개로 건강보험 질문 전부를 덮을 수 없다. **초기 무결과 비율은 높을 것이다.**
그래서 무결과 화면이 이 기능의 절반이다.

```
찾으시는 내용을 아직 다루지 못했습니다.

[피부양자 자격판정]  [지역가입자 보험료 계산]  [임의계속가입 비교]

찾던 내용을 알려주시면 다음 가이드에 반영하겠습니다. → 메일 보내기
확정적인 답변은 국민건강보험공단 1577-1000 이 가장 정확하고 빠릅니다.
```

메일 링크는 제목을 프리필한다: `mailto:...?subject=찾지 못한 질문`.
사용자가 스스로 보내는 것이므로 수집 이슈가 없고, 동의어 사전과 다음 가이드 주제의
유일한 입력 경로가 된다. 공단 안내를 함께 두는 것은 `contact` 페이지의 기존 입장과 같다.

## 10. 테스트 계획

### 단위 (vitest)

| 대상 | 내용 |
| --- | --- |
| `normalize` | 콤마·공백·구두점 제거, `2,000만원` = `2000만원` |
| `expandSynonyms` | 구어체 → 표준어 확장 |
| **랭킹 골든 테스트** | 대표 질문 20개 → 기대 1순위 엔트리 id 고정 |
| 인덱스 정합성 | 모든 엔트리의 `routeKey`가 `ready: true` |
| 커버리지 | `GUIDE_KEYS`의 모든 가이드가 인덱스에 1개 이상 |
| 임계값 | 무관한 질의("점심 메뉴")가 무결과인지 |

골든 테스트가 이 기능의 품질 게이트다. 동의어를 추가할 때 기존 20개가 깨지지 않는지 확인한다.

### E2E (playwright)

| 대상 | 내용 |
| --- | --- |
| 기본 흐름 | 홈에서 "연금" 입력 → 결과 → 클릭 → 해당 FAQ가 화면 안에 보임 |
| 앵커 정합성 | 인덱스의 모든 `anchor`가 대상 페이지 DOM에 실제로 존재 |
| 키보드 | 마우스 없이 검색 → `↓` → `Enter` 로 이동 |
| 모바일 | 375px에서 결과 목록이 하단 CTA를 가리지 않음 |
| JS 없이 | 홈의 자주 찾는 질문 6개가 정적 링크로 동작 |
| 이벤트 | `question_search`에 검색어 원문이 실리지 않음 |

마지막 항목은 방침 위반을 코드 레벨에서 막는 회귀 테스트다. 반드시 넣는다.
