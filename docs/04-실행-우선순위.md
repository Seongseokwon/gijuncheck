## 이 문서의 결론

P0 공개 기반 작업과 초기 검색 등록·색인 요청은 완료됐다. `gijuncheck.kr` 도메인을
구매·연결했고, 임시 Vercel 주소도 최종 도메인으로 리다이렉트되도록 처리했다. 최신 코드에는
canonical·`og:url`과 P0-3 출처·책임 범위가 반영돼 있다. 이제 병목은 **색인 결과를
관찰하면서 측정·공식 대조를 운영 루틴으로 연결하는 일**이다.

지역가입자 보험료는 2026-08-03 공단 공식 모의계산 13건 대조를 마쳤고, 임의계속가입 비교는
2026-08-03 현행 법령·공단 안내·보험료 고시와 대표 사례 대조를 마쳐 공개 기준을 충족했다.
다음 병목은 색인 결과를 관찰하면서 실제 사용성과 제도 변경을 운영 루틴으로 연결하는 일이다.

### 2026-08-04 기준 최근 반영

- P2-2 이후 QA 보강을 완료했다. 타입 검사·단위 테스트 136개·정적 빌드·Playwright 264개
  (241 통과, 23 스킵, 0 실패)가 통과했다. 공개 상태인데 기능 E2E가 없던 지역보험료
  계산기와 임의계속가입 비교에 각각 17개·11개를 추가했고, 공개 상태(`ready`)와 색인
  상태(`robots`)·sitemap의 정합성, GA4 이벤트의 범주값·원본 입력값 미전송, 대표 가이드
  모바일 렌더링을 자동 검사에 포함했다. 빌드 후 E2E 순서도 `verify` 스크립트로 고정했다.
  배포 후 실제 색인·공유 미리보기·공단 로그인 대조는 수동 확인 항목으로 남겼고, 테스트
  인벤토리는 `docs/06-QA-전수점검.md`에 기록했다.
- P0-2 공개 전 QA를 완료했다. 단위 테스트 114개와 정적 빌드가 통과했고, Playwright는
  117개를 실행해 108개 통과·8개 스킵·1개 타임아웃이었다. 타임아웃한 데스크톱 내부 링크
  크롤은 단독 재실행에서 통과했다. 이때의 타임아웃 원인은 P2-2 QA에서 규명했다 —
  빌드 중 실행으로 이전 산출물을 테스트한 것이며 앱 결함이 아니다(`06-QA-전수점검.md` Q1).

  매핑표, 대표 사례 대조표, 운영 주체·문의·개인정보 처리 범위를 반영했다.

### 피해야 할 경쟁 방식

다음은 이미 대체재가 강하거나, 기준체크가 주장하면 안 되는 영역이다.

- 공단보다 정확한 공식 판정이라고 주장하기
- 퇴직 후 지역·임의계속·피부양자 비교만으로 차별화하기
- 세금·N잡·사업자·부동산 등 모든 계산기를 한곳에 모으기
- 단순히 “출처 있음”, “입력값 서버 미전송”만으로 차별화하기

### 권장 포지션

> **퇴직 전후 건강보험 선택을 공단에 확인하기 전에, 관계·소득·재산 중 어디에서
> 결과가 갈리는지 공식 근거와 공개 검증 이력으로 설명하는 민간 참고 도구**

이 포지션은 공단의 공식 심사·신고 기능을 대체하지 않는다. 사용자가 공단에 가기 **전**에
자신의 상황을 구조화하고, 선택지·확인 항목·준비 자료·문의 질문을 알게 하는 보완 서비스다.

### 지금 주장할 수 있는 것과 주장하면 안 되는 것

- 주장 가능: 2026년 건강보험 3개 경로를 한 서비스에서 확인하고, 적용 기준·공식 출처·
  대조 범위·한계를 공개하는 민간 참고 도구다.
- 주장 가능: 지역보험료는 공단 모의계산 대표 13건을 대조한 범위를 공개한다.
- 조건부 주장: 임의계속가입 비교는 공식 법령·공단 산식 기반 참고 계산이며, 공단 로그인
  모의계산이나 개별 고지액을 직접 복제한다고 말하지 않는다.
- 주장 금지: 경쟁 서비스보다 무조건 정확하다, 공단보다 정확하다, 3경로 연결이 유일하다,
  출처가 있으므로 실제 고지액과 항상 일치한다.

### 다음 경쟁력 강화 과제

1. 세 도구 사이에서 이미 입력한 소득·재산·가족 조건을 더 많이 이어받게 해, 경쟁 서비스의
   통합 흐름 대비 재입력 부담을 줄인다.
2. 임의계속가입도 직접 공식 계산 결과를 확보할 수 있는 범위가 생기면, 현재의 법령·산식
   대조와 직접 대조를 구분해 검증기록에 추가한다.
3. 각 도구 화면 상단에 최종 검토일·기준연도·검증 상태를 더 짧게 노출해 검색 직접 유입자가
   홈이나 검증 원칙 페이지를 거치지 않아도 신뢰 신호를 확인하게 한다.
4. GA4에서 개인 입력값 없이 `도구 진입 → 계산 완료 → 공식 출처 클릭 → 다음 도구 이동`만
   측정해, 실제로 어떤 포지션 문구와 연결 흐름이 작동하는지 확인한다.
5. 경쟁 조사는 분기별로 갱신하되, 경쟁사의 기능을 복제하는 것보다 기준 변경 감지·대조
   사례·오류 정정 이력을 빠르게 공개하는 운영 루틴을 우선한다.

| 전환 경로 | 피부양자·지역보험료·임의계속가입을 공개하고 홈·결과 CTA로 연결함 | 세 도구 간 입력값 이어받기와 직접 공식 결과 대조를 확보함 |

### 반드시 지킬 안전 규칙

1. `NEXT_PUBLIC_SITE_URL`을 둔 임시 배포에서는 색인을 허용하지 않는다. 현재 코드가
   `robots.txt`와 메타데이터에서 이를 자동으로 막는다.
2. 최종 도메인을 구매·연결한 뒤에만 `src/lib/site.ts`의 `PRODUCTION_URL`을 바꾸고
   프로덕션을 배포한다. 아직 구매하지 않은 도메인을 canonical로 넣지 않는다.
3. `src/lib/routes.ts`의 각 기능은 자체 공식 대조가 완료되기 전까지 `ready: false`를
   유지한다. 현재 지역보험료와 임의계속가입 비교는 공식 기준 대조 완료로 공개됐고,
   국민연금·고용보험 도구는 아직 `ready: false`다.
4. 법령·요율을 바꾸면 코드, 테스트, 화면 문구, 검증기록을 같은 변경 묶음으로 갱신한다.
5. 분석 도구에는 소득·재산·관계처럼 개인을 추정할 수 있는 입력값을 보내지 않는다.

## 배포 체크리스트

배포 전과 배포 후에 아래를 매번 확인한다.

```powershell
npm test
npm run build
```

- [ ] `out/`에 정적 파일이 생성됐다.
- [ ] 최종 도메인 `robots.txt`가 전체 차단 상태가 아니며 sitemap 주소를 반환한다.
- [ ] `sitemap.xml`에 공개·색인 대상 페이지만 있다.
- [ ] canonical, `og:url`, JSON-LD URL이 최종 도메인으로 일치한다.
- [ ] OG 이미지 URL이 200으로 열리고, 카카오 공유 캐시 갱신이 필요하면 카카오 개발자 도구에서
      해당 페이지 캐시를 초기화한다.
- [ ] 별도 공식 대조가 끝나지 않은 기능은 메뉴·홈·sitemap에서 노출되지 않는다. 현재는
      국민연금·고용보험 도구가 이 조건에 해당한다.
- [ ] 배포 URL에서 모바일 폼과 결과 화면을 한 번 실제로 입력해 본다.
- [ ] 네이버 소유확인 태그와 Google Search Console 속성 확인이 최종 도메인에서 성공한다.

## 하지 않을 일

- 검증되지 않은 계산기를 “참고용”이라는 문구만 붙여 공개하지 않는다.
- 최종 도메인 전의 임시 URL을 검색엔진에 등록하지 않는다.
- AI 생성 문구를 출처·검토 없이 법령 설명으로 게시하지 않는다.
- FAQ 구조화 데이터에 화면에 없는 질문·답변을 넣지 않는다.
- 트래픽이 없다는 이유만으로 광고 위치를 폼 안으로 옮기지 않는다.
