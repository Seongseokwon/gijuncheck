## 이 문서의 목적

전수 QA에서 **무엇을 자동으로 지키게 만들었고, 무엇이 아직 사람 손에 남아 있는지**를
남긴다. 이어받는 작업자는 3절(조치 항목)만 보고 실행하면 되고, 새 기능을 붙일 때는
2절(테스트 인벤토리)에서 어느 파일에 테스트를 추가할지 판단한다.

**현재 상태: 자동 QA 항목 통과.** Q1~Q3와 Q5~Q8, Q10은 자동화로 닫았고, Q4와 Q11은
최종 도메인과 검색엔진·공유 서비스의 외부 상태가 필요하므로 운영 확인 대기로 남긴다.

### 이번에 추가한 테스트와 그 이유

**`e2e/regional-premium.spec.ts` (신규 17개)**
기대 금액은 `src/lib/premium/regional.test.ts` 의 공단 모의계산 13건과 **같은 값**을
쓴다. 단위 테스트는 계산식을, 이 파일은 그 값이 실제 화면까지 도달하는지를 본다.

- 근로 500만 + 연금 500만 = 사업소득 500만 → 50% 반영 증명. 이걸 100%로 반영하면
  주 타깃인 연금 수령자의 보험료가 2배가 된다
- 재산 기본공제 1억 경계(1억 → 0원, 1억 1만 → 4,653원), 하한 22,800원, 상한 4,591,740원
- 전월세 환산 `(보증금 + 월세 × 40) × 30%` = 1억 2,600만 → 재산보험료 30,879원
- 판정기에서 넘어온 sessionStorage 자동 채움, 임의계속가입 CTA가 재산금액을 들고 이어지는지
- 대조 완료 상태이므로 "참고용" 미검증 배지가 뜨지 않는지
- 근거·면책·비전송 고지, 키보드 조작, 모바일 16px, 결과 후 가로 스크롤

**`e2e/voluntary-continuation.spec.ts` (신규 11개)**
이 화면의 위험 두 가지를 정면으로 겨냥했다.

- **신청기한을 "퇴직 후 90일"로 안내하지 않는지.** 낡은 기준이고, 믿으면 사용자가
  기한을 놓쳐 그 기간 지역보험료를 그대로 부담한다
- **"임의계속이 항상 싸다"는 인상을 주지 않는지.** 재산 9억이면 임의계속,
  퇴직 전 보수 1,200만이면 지역가입자로 결론이 뒤집히는지 양방향으로 확인
- 12개월 미만 신청 불가 분기, 보수 외 소득 2,000만 경계의 추가 보험료 줄 노출·미노출
- 보수 외 소득보험료는 **금액이 아니라 존재 여부**만 고정했다. 금액의 정확성은 단위
  테스트가 보는 영역이고, 화면 테스트가 금액까지 잡으면 산식을 손볼 때마다 함께 깨진다

**`e2e/og-meta.spec.ts` (2개 추가)**
`ready` 를 뒤집을 때 페이지의 `robots` 와 sitemap 을 같이 고치는 걸 잊기 쉽다.
어긋나면 양방향 모두 손해다 — 공개했는데 noindex 면 검색에 영원히 안 잡히고,
대조 전인데 index 면 검증 안 된 계산 결과가 검색에 노출된다.

- 공개된 도구는 색인 가능, 비공개 도구는 noindex — 레지스트리와 실제 메타 태그 대조
- sitemap 이 `indexableRoutes()` 결과와 **정확히 일치**하는지, `lastmod`가 빌드 시각이
  아니라 경로별 `ROUTES[*].lastModified`의 안정적인 날짜인지 함께 검사한다. 기존 테스트는 200 응답만
  확인해서 누락·과다 등록과 날짜 변동을 잡지 못했다

**`e2e/analytics.spec.ts` (신규 4개)와 대표 가이드 모바일 검사 (신규 2개)**

- 홈 CTA, 피부양자 판정 시작·완료, 지역보험료 계산, 임의계속가입 비교 이벤트가 실제
  `gtag` 호출로 이어지는지 확인한다.
- 이벤트에는 boolean·enum·관계 코드만 남고, 테스트 입력에 사용한 금액이 페이로드에
  포함되지 않는지 확인한다.
- 긴 본문과 출처 목록이 있는 재산세 과세표준·자격상실 가이드의 모바일 가로 스크롤과
  출처 블록 노출을 대표 샘플로 확인한다.

**`e2e/guide-quality.spec.ts` 구조화 데이터 검사 (추가 1개)**

- 가이드 Article에 `author`, `publisher`, `image`가 있는지 확인한다.
- 가이드 6편과 도구 3개에 `BreadcrumbList`가 있고, 두 항목의 URL·순서가 현재 페이지와
  일치하는지 확인한다.

**`e2e/dependent-judge.spec.ts` 0원 모달 회귀 검사 (추가 2개)**

- 0원 항목이 있으면 결과를 바로 노출하지 않고 확인 모달이 먼저 나타나는지 확인한다.
- 모달의 backdrop이 `0,0`부터 viewport 전체를 덮고, 대화상자가 화면 중앙에 위치하며,
  CSS blur가 적용되는지 확인한다. 구현은 Portal 기반이라 sticky header의 stacking context에
  가려지는 회귀를 방지한다.

**2단계 접근성·신뢰 보강 검사**

- 도움말은 이미지가 아닌 키보드로 조작 가능한 버튼이며, 라벨·설명·열림 상태를 보조기기에
  전달한다. 모바일 터치 타깃은 44px 이상이다.
- 0원 확인 모달은 열릴 때 포커스를 내부에 가두고, `Escape`로 닫히며, 닫힌 뒤 제출 버튼으로
  포커스를 복원한다. 모달 뒤의 문서 형제에는 열려 있는 동안 `aria-hidden`을 적용한다.
- 임의계속가입 비교의 `ReferenceOnlyNotice`와 피부양자 `TrustSignal`은 직접 공단 심사를
  대조한 것처럼 보이지 않도록 자체 재현·참고 계산 상태를 구분한다.

**Vercel Speed Insights 처리**

- `src/app/layout.tsx`의 `SpeedInsights`는 Production에서만 의미 있는 외부 수집 경로를
  만든다. 로컬 E2E에서는 `/_vercel/speed-insights/**`를 200 응답으로 모킹해 분석 도구
  연결 때문에 콘솔 오류가 발생하지 않는지만 검사한다.

### [x] Q6. 하위 페이지 `og:url`이 홈 URL로 고정되는 문제

빌드 산출물에서 가이드·도구 페이지의 canonical은 자기 URL이었지만 `og:url`은 홈 URL로
고정되어 있었다. 공유 미리보기와 페이지 식별이 어긋날 수 있는 SEO 결함이다.

**조치:** `src/lib/metadata.ts`의 공통 생성 함수로 canonical 경로를 절대 URL로 변환해
페이지별 `og:url`에 사용했다. 같은 함수에서 OG title·description·이미지·Twitter metadata를
함께 생성하며, 가이드 페이지는 `article`, 나머지는 `website`로 구분한다.

**완료 기준:** ready 페이지 전체에서 canonical과 `og:url`이 동일하고, OG title·description이
비어 있지 않은지 `e2e/og-meta.spec.ts`로 확인한다. — 5개 통과

### [x] Q7. sitemap `lastmod`가 매 빌드 시각으로 변하는 문제

내용이 바뀌지 않은 배포에서도 `new Date()`가 모든 URL의 `lastmod`를 갱신해 검색엔진에
불안정한 신선도 신호를 보낼 수 있었다.

**조치:** `src/app/sitemap.ts`가 각 공개 경로의 실제 콘텐츠·기준 변경일을 나타내는
`ROUTES[*].lastModified`를 사용하도록 변경했다. 페이지 내용이나 기준이 바뀐 경로만
`src/lib/routes.ts`에서 명시적으로 갱신하며, 빌드 시각은 sitemap에 기록하지 않는다.

**완료 기준:** 정적 산출물의 모든 공개 URL이 `YYYY-MM-DD` 형식의 경로별 변경일을 사용하고,
`e2e/og-meta.spec.ts`에서 경로·값 쌍과 URL 수를 함께 검사한다. — 통과

### [x] Q9. 홈·404·가이드의 저비용 SEO 메타데이터 누락

홈이 전역 description을 그대로 사용하고, 404가 레이아웃의 홈 canonical을 상속하며,
가이드의 화면상 발행일이 기계 판독 가능한 날짜 요소로 표시되지 않는 문제가 있었다.

**조치:** 홈에 고유 description과 OG description을 지정하고, 404에 `canonical: null`을
설정했다. 공개·정책 페이지의 canonical이 자기 URL인지와 404 canonical 부재를 E2E로 검사하며,
가이드의 발행일·최종 확인일을 `<time dateTime>`으로 출력한다.

**완료 기준:** TypeScript 검사·정적 빌드 통과, `e2e/og-meta.spec.ts`와
`e2e/guide-quality.spec.ts`의 저비용 SEO 회귀 검증 통과.

### [x] Q8. 구조화 데이터의 주체·계층 정보와 FAQ 설명이 부족한 문제

가이드 Article에 작성 주체·publisher·image가 없었고, 가이드·도구의 사이트 내 위치를
표현하는 `BreadcrumbList`도 없었다. FAQ 구조화 데이터 주석과 기획 문서는 일반 사이트에서
Google FAQ 리치 결과가 넓게 노출되는 것처럼 설명하고 있었다. — [Google Search Central 공식 안내](https://developers.google.com/search/blog/2023/08/howto-faq-changes)

**조치:** `src/components/guide.tsx`의 공통 Article JSON-LD에 author·publisher·image를
추가하고, `src/lib/structured-data.ts`의 공통 함수로 가이드 6편과 도구 3개에
`BreadcrumbList`를 추가했다. FAQPage는 화면에 표시되는 FAQ를 설명하는 보조 데이터로
유지하되 검색 결과 노출을 보장한다는 설명은 제거했다.

**완료 기준:** 가이드·도구 JSON-LD를 `e2e/guide-quality.spec.ts`로 검사하고, FAQ 관련
문서·주석이 검색 결과 면적 확대를 전제로 하지 않는다. — 1개 통과

### [x] Q10. 모든 페이지가 같은 OG 이미지로 공유되는 문제

기존에는 페이지 주제와 무관하게 `public/og.png` 하나를 모든 페이지가 사용해, 가이드·도구를

1차 측정에서 이 글을 미색인으로 **잘못 기록했고**, 확인차 GSC URL 검사를 돌린 결과

| 항목 | 값 |
|---|---|
| 참조 페이지 | `https://gijuncheck.kr/sitemap.xml` |
| 최근 크롤링 | 2026-08-04 02:18 (Googlebot 스마트폰) |

빌드 산출물을 확인한 결과 원인이 현재 코드에 없다.

```

src/app/layout.tsx : metadataBase: new URL(SITE.url)
```

`grep -rn "http://gijuncheck" src/ public/ out/` → **소스·빌드 산출물 모두 0건.**
사이트가 자기 자신을 http로 링크하는 곳은 없다.

10:07로 도메인 연결 직후**이므로, 그때 Googlebot이 받은 것이 현재의 페이지가 아니었을

##### 서버 응답 확인 — 정상 (2026-08-06)

```
$ curl.exe -I http://gijuncheck.kr/
HTTP/1.0 308 Permanent Redirect
Location: https://gijuncheck.kr/
server: Vercel
```

**영구 리다이렉트가 정상적으로 나간다.** Google은 308을 301과 동일한 영구 리다이렉트로
취급한다. 서버·도메인 설정에 고칠 것이 없다.

> **측정 함정 (두 번째로 밟았다).** 처음에는 브라우저로 `http://gijuncheck.kr/` 에
> 접속해 https로 이동하는 것을 보고 "리다이렉트 정상"이라고 기록했다. **이것은 증명이
> 아니다.** `vercel.json`이 `Strict-Transport-Security ... preload` 를 보내므로 한 번
> https를 방문한 브라우저는 **서버에 묻지 않고 스스로 https로 올린다.** 서버 동작을
> 확인하려면 반드시 `curl -I` 로 응답 코드를 본다. HSTS는 브라우저용 신호이고
> Googlebot의 URL 정규화를 대신하지 않는다.
