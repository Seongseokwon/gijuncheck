# QA 전수 점검 기록 (P2-2 이후 QA 보강)

작성일: 2026-08-03
대상: P2-2 이후 QA 보강 작업과 현재 정적 빌드
관련 문서: [실행 우선순위](./04-실행-우선순위.md) P0-2·P2-1·P2-2 · [검증기록](./03-검증기록.md)

## 이 문서의 목적

전수 QA에서 **무엇을 자동으로 지키게 만들었고, 무엇이 아직 사람 손에 남아 있는지**를
남긴다. 이어받는 작업자는 3절(조치 항목)만 보고 실행하면 되고, 새 기능을 붙일 때는
2절(테스트 인벤토리)에서 어느 파일에 테스트를 추가할지 판단한다.

**현재 상태: 자동 QA 항목 통과.** Q1~Q3는 자동화로 닫았고, Q4는 최종 도메인과
검색엔진·공유 서비스의 외부 상태가 필요하므로 운영 확인 대기로 남긴다. Q5는 이번
변경 묶음에 포함한다.

점검을 시작할 때 HEAD 는 P1-5 였는데 작업 중 `11795a8`(P2-1)·`084f8ce`(P2-2)가

화면이 검증 없이 남으므로** P2-2 를 범위에 포함했다.

**공개된 계산기 두 개에 기능 E2E 가 하나도 없었다.** `e2e/pages.spec.ts` 가 레이아웃과
가로 스크롤만 확인하고 있어서, 보험료 금액이 틀려도 E2E 는 전부 통과했다. 피부양자
판정기는 16개로 촘촘한데 정작 "얼마 내는지"를 말하는 화면이 무방비였다.

## 2. 테스트 인벤토리

새 기능을 붙이거나 기존 화면을 고칠 때 **어느 파일을 함께 고쳐야 하는지**의 지도다.
개수는 뷰포트 1개(desktop-1440) 기준이며, 실제 실행은 3개 프로젝트
(desktop-1440 / tablet-768 / mobile-375)에서 반복된다.

| 파일 | 개수 | 지키는 것 |
| --- | --- | --- |
| `e2e/pages.spec.ts` | 20 | 전 공개 경로의 로드·가로 스크롤·콘솔 에러, 홈 CTA·모바일 메뉴, 도구 카드 공개 상태 |
| `e2e/dependent-judge.spec.ts` | 16 | 피부양자 판정 — 관계별 분기, 소득 2,000만·재산 5.4억/9억 경계, 사업자등록 특례, 근거 링크, 신청 준비 체크리스트 |
| `e2e/regional-premium.spec.ts` | 17 | 지역보험료 — 소득 반영률, 재산 기본공제 경계, 상·하한, 전월세 환산, 판정기 연계, 검증 배지 |
| `e2e/voluntary-continuation.spec.ts` | 11 | 임의계속가입 — 자격 분기, 결론 역전, 신청기한 문구, 보수 외 소득 경계 |
| `e2e/guide-quality.spec.ts` | 8 | 가이드 6편의 한 줄 답변·FAQ·출처·내부 링크, 대표 2편 모바일 렌더링 |
| `e2e/og-meta.spec.ts` | 5 | canonical·OG, 정책 페이지 noindex, **공개 상태와 색인 상태 정합성**, **sitemap 일치** |
| `e2e/analytics.spec.ts` | 4 | GA4 핵심 이벤트 발화와 허용 범주값, 원본 입력값 미전송 |
| `e2e/keyboard-a11y.spec.ts` | 4 | 키보드만으로 판정 완주, 툴팁 포커스, 모바일 입력 16px |
| `e2e/links.spec.ts` | 3 | 외부 링크 새 탭·noopener, 내부 링크 전수 크롤, sitemap URL 200 |

### 이번에 추가한 테스트와 그 이유

**`e2e/regional-premium.spec.ts` (신규 17개)**
기대 금액은 `src/lib/premium/regional.test.ts` 의 공단 모의계산 13건과 **같은 값**을
쓴다. 단위 테스트는 계산식을, 이 파일은 그 값이 실제 화면까지 도달하는지를 본다.

- 근로 500만 + 연금 500만 = 사업소득 500만 → 50% 반영 증명. 이걸 100%로 반영하면
  주 타깃인 연금 수령자의 보험료가 2배가 된다
- 재산 기본공제 1억 경계(1억 → 0원, 1억 1만 → 4,653원), 하한 22,800원, 상한 4,591,740원
- 전월세 환산 `(보증금 + 월세 × 40) × 30%` = 1억 2,600만 → 재산보험료 30,879원
- 판정기에서 넘어온 쿼리 자동 채움, 임의계속가입 CTA 가 재산금액을 들고 이어지는지
- 대조 완료 상태이므로 "참고용" 미검증 배지가 뜨지 않는지
- 근거·면책·비저장 고지, 키보드 조작, 모바일 16px, 결과 후 가로 스크롤

**`e2e/voluntary-continuation.spec.ts` (신규 11개)**
이 화면의 위험 두 가지를 정면으로 겨냥했다.

- **신청기한을 "퇴직 후 90일"로 안내하지 않는지.** 낡은 기준이고, 믿으면 사용자가
  기한을 놓쳐 그 기간 지역보험료를 그대로 부담한다
- **"임의계속이 항상 싸다"는 인상을 주지 않는지.** 재산 9억이면 임의계속,
  퇴직 전 보수 1,200만이면 지역가입자로 결론이 뒤집히는지 양방향으로 확인
- 12개월 미만 신청 불가 분기, 보수 외 소득 2,000만 경계의 추가 보험료 줄 노출·미노출
- 보수 외 소득보험료는 **금액이 아니라 존재 여부**만 고정했다. 금액의 정확성은 단위
  테스트가 보는 영역이고, 화면 테스트가 금액까지 잡으면 산식을 손볼 때마다 함께 깨진다

**`e2e/og-meta.spec.ts` (2개 추가)**
`ready` 를 뒤집을 때 페이지의 `robots` 와 sitemap 을 같이 고치는 걸 잊기 쉽다.
어긋나면 양방향 모두 손해다 — 공개했는데 noindex 면 검색에 영원히 안 잡히고,
대조 전인데 index 면 검증 안 된 계산 결과가 검색에 노출된다.

- 공개된 도구는 색인 가능, 비공개 도구는 noindex — 레지스트리와 실제 메타 태그 대조
- sitemap 이 `indexableRoutes()` 결과와 **정확히 일치**하는지. 기존 테스트는 200 응답만
  확인해서 누락·과다 등록을 잡지 못했다

**`e2e/analytics.spec.ts` (신규 4개)와 대표 가이드 모바일 검사 (신규 2개)**

- 홈 CTA, 피부양자 판정 시작·완료, 지역보험료 계산, 임의계속가입 비교 이벤트가 실제
  `gtag` 호출로 이어지는지 확인한다.
- 이벤트에는 boolean·enum·관계 코드만 남고, 테스트 입력에 사용한 금액이 페이로드에
  포함되지 않는지 확인한다.
- 긴 본문과 출처 목록이 있는 재산세 과세표준·자격상실 가이드의 모바일 가로 스크롤과
  출처 블록 노출을 대표 샘플로 확인한다.

## 3. 조치 항목

### [x] Q1. E2E 는 빌드를 끝낸 뒤에 실행한다

점검 중 4개·15개씩 실패하는 실행이 있었는데 **앱 결함이 아니었다.** `out/` 을 다시
빌드하는 동안 테스트가 돌아 생긴 실패다.

`playwright.config.ts` 의 `reuseExistingServer: !process.env.CI` 는 이미 떠 있는 서버를
재사용하는데, 그 서버가 이전 산출물을 들고 있으면 **방금 고친 코드가 아니라 옛 빌드를
테스트한다.** 실패한 케이스를 단독 재실행하면 전부 통과했고, 빌드를 끝낸 뒤에는 워커
4개·8개 모두에서 5회 연속 깨끗했다.

`docs/04-실행-우선순위.md` P0-2 기록의 "1개 타임아웃, 단독 재실행에서 통과" 도 같은
원인으로 보인다.

**조치:** `npm run verify` 를 `typecheck → unit test → build → test:e2e` 순서로 변경했고,
`npm run verify:e2e` 를 `build → test:e2e` 전용 명령으로 추가했다. `playwright.config.ts`도
기본적으로 기존 정적 서버를 재사용하지 않으며, 필요한 경우에만
`REUSE_E2E_SERVER=true`를 명시한다.

**완료 기준:** 빌드와 E2E의 순서가 스크립트로 고정되고, 이 규칙이 문서에 남는다. — 완료

### [x] Q2. GA4 이벤트 발화가 E2E 로 검증되지 않는다

`premium_calculate`(지역보험료), `voluntary_compare`(임의계속가입),
`home_cta_click`·`judge_start`·`judge_complete` 는 코드에 있지만 **실제로 발화하는지를
자동으로 확인하지 않는다.** P1-2 는 사용자가 실시간 보고서에서 눈으로 확인한 상태다.

이벤트가 조용히 죽으면 유입·전환 데이터가 사라지고, 그 사실을 몇 주 뒤에나 안다.

**조치:** `e2e/analytics.spec.ts`에서 `gtag` 할당을 가로채 홈 CTA·판정 시작·판정 완료·
지역보험료 계산·임의계속가입 비교 이벤트의 발화를 확인한다. 금액을 테스트 입력으로
넣은 뒤에도 이벤트에는 boolean·enum·관계 코드만 남는지 함께 확인한다. 실제 GA4 네트워크
전송이나 측정 ID에 의존하지 않으므로 로컬 빌드에서도 개인정보 규칙을 회귀 검사한다.

**완료 기준:** 핵심 이벤트 3종 이상의 발화와 페이로드 범주값이 E2E로 고정된다. — 완료

### [x] Q3. 가이드 품질 검사가 데스크톱 단일 뷰포트다

`e2e/guide-quality.spec.ts` 는 6편을 desktop-1440 에서만 본다. 가이드는 검색 유입의
대부분이 모바일인데, 표·각주·출처 목록이 좁은 폭에서 깨지는지는 `pages.spec.ts` 의
가로 스크롤 검사에만 의존한다.

**조치:** 재산세 과세표준·자격상실 가이드 2편을 대표 샘플로 선정해 모바일 프로젝트에서
가로 스크롤·제목·출처 블록을 추가 확인한다. 6편 전체는 기존 독립 유입 품질 검사로
유지하고, 대표 샘플만 모바일에서 반복해 실행 시간을 통제한다.

**완료 기준:** 대표 가이드의 모바일 렌더링이 자동 검사에 포함된다. — 완료

### [ ] Q4. 자동화 밖에 남은 수동 확인 — 배포 후 운영 확인 대기

다음은 로컬 정적 서버에서 확인할 수 없다. 배포 후 사람이 본다.

## 4. 회귀 시 함께 고칠 곳

연도 기준이나 요율이 바뀌면 아래를 **한 변경 묶음**으로 갱신한다. 하나만 고치면
테스트가 통과하면서 화면만 틀리거나, 그 반대가 된다.

| 바뀌는 것 | 함께 고칠 파일 |
| --- | --- |
| 소득·재산 판정 기준액 | `src/lib/constants/2026.ts`, `e2e/dependent-judge.spec.ts` 상단 리터럴 |
| 보험료율·재산 등급표·상하한 | `src/lib/constants/2026.ts`, `src/lib/premium/regional.test.ts` 의 공단 대조 13건, `e2e/regional-premium.spec.ts` 의 기대 금액 |
| 임의계속가입 산식·경감률 | `src/lib/premium/regional.ts`, 같은 파일의 단위 테스트, `e2e/voluntary-continuation.spec.ts` |
| 도구 공개 여부(`ready`) | `src/lib/routes.ts`, 해당 페이지의 `robots`, 홈 카드 문구, `e2e/og-meta.spec.ts` 정합성 검사가 자동으로 잡는다 |
| 신고기한·신청 경로 안내 | `src/lib/dependent/application.ts`, `src/lib/dependent/sources.ts`, `docs/05-P1-5-체크리스트-보완.md` 8.4 표 |

E2E 가 상수 파일을 직접 import 하지 않고 리터럴을 쓰는 이유는 Playwright 가
`tsconfig` 의 `@/` 경로를 해석하지 못하기 때문이다. 대신 **바뀌면 반드시 깨지도록**
기대값을 명시적으로 적어둔다.

## 5. 점검 중 관찰한 것

- 세션 중간에 단위 테스트 1건(`보수 외 소득 추가분 50% 반영`)이 실패 상태였다.
  기대 209,708원에 실제 104,854원으로 정확히 절반이었다 — 소득월액보험료에 경감률이
  잘못 걸린 형태였다. 점검을 정리하는 사이 수정되어 최종 상태는 136개 전부 통과다.
- `Object.values(ROUTES)` 는 유니온 타입이라 `noindex` 를 선언하지 않은 항목에서 그
  속성이 사라진다(`routes.ts` 말미 주석과 같은 문제). E2E 에서도 같은 함정을 밟았고,
  `RouteEntry[]` 로 받아 해결했다. 새 테스트에서 경로를 순회할 때 주의한다.

## 6. 작업 메모

이어받는 작업자가 채운다. 조치한 항목, 다르게 판단한 이유, 확인하지 못한 것을 남긴다.

- Q1은 빌드 중 기존 `out/`을 대상으로 E2E가 실행될 수 있었던 문제를 스크립트와
  Playwright 서버 재사용 기본값 변경으로 닫았다.
- Q2는 GA4 실시간 보고서 확인을 대체하지 않는다. 실측 전송은 별도 운영 점검으로 남지만,
  이벤트 코드의 발화와 원본 입력값 미전송은 로컬 회귀 테스트로 고정했다.
- Q3는 6편 전체를 모바일 반복하지 않고 레이아웃이 긴 대표 2편을 선택했다. 새 표·긴
  출처 목록이 추가되면 대표 샘플을 다시 선정한다.
- Q4의 색인·공유 미리보기·공단 로그인 결과는 외부 상태라 자동 QA 완료로 표시하지 않는다.
- Q5는 사용자가 작업 중이던 `e2e/og-meta.spec.ts`를 임의로 되돌리지 않고 이번 QA 변경과
  함께 커밋한다.
