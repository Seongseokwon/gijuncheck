# 방향 C 반론/수정 — 3단계 반론 라운드

## 결론 먼저

4개 비평 중 법적 리스크(보통)·접근성(조건부)의 지적은 전부 **수용**하고 구체 값을 바꾼다. 유지보수(실패)는 **부분 수용 + 잔여 실패를 명시적으로 인정**한다(8h 미만 달성은 이 mandate 안에서 불가능하다). 유입(취약)의 핵심 지적 — "조항별 정적 랜딩이 설계에 없다" — 은 **가장 무겁게 받아들여 홈·가이드 관계를 재설계**한다. mandate C(검증 가능성 최대화)는 그대로 유지하며, 어느 항목도 이를 피하려고 방향을 바꾸지 않았다.

## 3. 유지보수 비평("실패", 10.5h/216지점) — 부분 수용 + 잔여 실패 인정

### 받아들이지 않는 부분 (거부)
`lastChecked` 필드는 원래 내가 7절에서 정의한 `{value, statute, effectiveDate, verified}` 4필드에 없던 것이며, 이후 codex 피드백이 별도로 덧붙인 5번째 필드다. 유지보수 비평이 지적한 "상시 갱신 압박"(값이 안 바뀌어도 확인 날짜만 계속 찍어야 하는 문제)은 이 필드 하나에서 대부분 발생한다. **mandate C는 "이 값이 언제 확인됐는가"를 상시 노출할 것을 요구하지 않는다 — "이 값의 근거가 무엇인가"를 요구할 뿐이다.** 따라서 `lastChecked`를 채택하지 않는다. 대신 `verified` 상태(검증됨/미검증 이분법)만 유지하고, 최종 검증 일자는 화면이 아니라 내부 커밋 로그·CHANGELOG로만 관리한다(사용자에게 "이건 언제 확인한 값인가"라는 새로운 신뢰 축을 만들지 않는다).

### 받아들이는 부분 (구체 변경)
1. **메타데이터 4필드 유지, 5필드 거부** — 위 결정.
2. **마진노트를 "요약 인용 + 링크"로 축소**: 기존에는 마진노트 안에 조항 번호와 설명을 매 필드마다 완결된 문장으로 반복 기재했다("형제자매는 소득요건 외... 국민건강보험법 시행규칙 별표1의2 제3호" 전문 반복). 이를 `[별표1의2 제3호]` 형태의 짧은 인용 배지 + `자세히 보기 → [해당 가이드 앵커]` 링크로 바꾼다. 상세 설명은 4절 유입 재설계(아래)에서 가이드 문서 쪽으로 이관한다. 결과적으로 동일 조항을 인용하는 여러 입력 필드(예: 5종 소득 필드가 모두 같은 소득요건 조항을 인용하는 경우)가 문구를 각각 따로 유지할 필요 없이 가이드의 해당 문단 하나만 갱신하면 된다.
3. 이에 따라 화면 문구 수정 공수를 재추정한다: 개정 파악·확인 2.5h(불변) + 코드 상수 수정 1.2h(4필드로 축소, 5필드였을 때보다 감소) + 화면 문구 수정 1.3h(11개 필드 전문 반복 → 짧은 인용 배지로 축소, 기존 2.5h에서 감소) + 검증·회귀 테스트 1.7h(중복 인용 제거로 대조 지점 감소, 기존 2h에서 소폭 감소) + 가이드 6편 갱신 2h(공통 비용, 불변) = **약 8.7h**.

### 잔여 실패 인정
8.7h는 여전히 8h 기준을 초과한다. **이 이하로는 mandate C 안에서 내려갈 수 없다고 인정한다.** 조항 번호·시행일의 정확성 검증은 법제처 원문을 사람이 열어 대조하는 작업이라 코드 diff로 자동화되지 않으며, 이는 "추적 가능성"이라는 목적함수 자체에서 발생하는 비용이지 설계 실수가 아니다. 이 잔여 초과분(0.7h)을 없애려면 조항 번호·시행일 표기 자체를 없애야 하는데, 그러면 mandate C의 핵심(법령 근거·기준 연도를 전면에 드러낸다)이 무너진다. 즉 **유지보수 실패 판정은 완전히 해소되지 않으며, 이는 mandate C를 채택한다면 조직이 감수해야 할 고정비용이다.**

## 4. 유입 비평("취약", 결정적 결함) — 정면 대응: 조항별 정적 랜딩을 실제로 설계한다

지적을 그대로 인정한다: 3~5절 어디에도 검색엔진이 도달할 조항 단위 정적 페이지가 없었다. 이것은 mandate C가 "가이드 6편이 본체이고 판정기는 그 안에 놓인 도구"라는 정의를 스스로 지키지 못한 것이었다 — 원안은 가이드를 8절에서 "확장성 있는 허브 정체성"을 포기하는 맥락에서만 스치듯 언급했을 뿐, 가이드를 유입·정보구조의 중심으로 설계하지 않았다. **이것은 mandate C 안에서 고칠 수 있는 문제이지, mandate와 충돌하는 문제가 아니다.** 오히려 가이드를 중심에 놓는 쪽이 판정 도구 하나만으로 검증 가능성을 감당하려던 원안보다 mandate에 더 충실하다.

### 유입 가정 재정의 (2절 갱신)
- **기존**: "피부양자 재산과세표준 5.4억 근거", "국민건강보험법 시행령 제41조" 같은 조항 번호 직접 검색 → 개별 근거 페이지 직접 랜딩.
- **수정**: codex 피드백의 재구성을 그대로 받아들인다. 조항 번호 자체를 검색하는 사용자는 소수이며, 실제로는 "부모님 피부양자 조건", "피부양자 재산요건" 같은 **주제/요건 단위 정보형 검색**이 대다수다(브랜드 도구 검색과는 별개). 이 정보형 검색에서 신뢰도 높은 랜딩 지점으로 연결되는 경로가 약하다는 것이 문제였지, "조항 검색이 전혀 없다"는 게 아니다.
- 첫 화면으로 가정하는 페이지: 홈이 아니라 **가이드 개별 페이지**(주제 단위). 조항 번호는 그 가이드 본문 안의 앵커로 존재한다.

### 구체 URL·구조 설계
- 가이드 6편을 각각 정적 페이지로 노출: `/guides/[topic-slug]` (예: `/guides/property-requirement`, `/guides/income-requirement` — 실제 슬러그·제목은 Brief의 가이드 목차를 그대로 따르며, 여기서는 예시로만 사용한다는 점을 명시한다).
- 각 가이드 본문 안에서 조항이 등장하는 지점마다 안정적 앵커 ID를 부여: `## 재산과세표준 5.4억원 기준 {#시행령-제41조}` → URL `/guides/property-requirement#시행령-제41조`. 이는 개별 조항 전용 페이지는 아니지만(그 정도로 세분화하면 갱신 지점이 폭증해 3절 유지보수 문제를 악화시킨다), 검색엔진이 색인할 수 있는 **주제 단위 정적 페이지 + 조항 단위 딥링크**를 실제로 만든다.
- 가이드 본문 중 판정과 직결되는 문단 끝에 고정 CTA 삽입: `이 기준으로 직접 계산해보기 → /tool?focus=property` (판정 도구의 재산요건 카드로 스크롤 이동).
- 판정 도구의 마진노트(3절에서 축소한 짧은 인용 배지)는 반대 방향으로 링크: `자세히 보기 → /guides/property-requirement#시행령-제41조`. 즉 가이드와 도구가 양방향으로 연결된 그래프를 이룬다.

### 홈 구조 재정의 (3절 갱신)
기존 "조항 색인"(법령 조항 번호 나열)을 **"가이드 주제 목차"**로 바꾼다. 홈에는 6개 가이드 카드(제목 + 한 줄 요약 + 다루는 조항 2~3개 미리보기)와 판정 도구 진입점 1개를 나열한다. 브랜드 설득 문구·CTA 강조는 여전히 두지 않는다(원안의 절제 원칙 유지) — 다만 조항 번호 대신 사람이 실제로 검색할 법한 요건 이름(재산요건, 소득요건 등)을 1차 표제로 쓴다는 점만 바뀐다. 이는 "마케팅적 설득을 배제한다"는 원안의 태도를 버리는 것이 아니라, "검색 가능한 자연어 제목"과 "설득 문구"를 구분한 것이다.

### 이 변경이 3절의 나머지 항목에 미치는 영향
검색 표면이 기존 "홈 1 + 판정기 1"에서 **"홈 1 + 가이드 6 + 판정기 1" = 8개 인덱싱 가능 페이지**로 늘어난다. 유지보수 비평이 지적한 "가이드 6편 68건"은 원래도 공통 갱신 표면에 포함돼 있었으므로 이 변경이 유지보수 부담을 새로 만들지는 않는다 — 오히려 마진노트 중복 설명을 가이드로 이관해 3절에서 이미 부담을 줄였다.

## 5. 최종 입장

mandate C는 그대로다: 판정 결과를 스스로 재현·검증할 수 있게 하는 것이 목적함수다. 이번 라운드에서 바뀐 것은 세 가지뿐이다.

1. **경계 표시 강화** — 브랜드 바, 원문/해설 라벨, 미검증 칩 배경. 법적 리스크를 낮추면서 mandate C가 원래 의도한 "무엇이 원문이고 무엇이 우리 해설인지"의 구분을 오히려 더 명확하게 만든다.
2. **팔레트·타이포 3곳 수정** — 테두리 `#71717A`, 각주 14px, 입력 필드 16px, 터치타겟 44px. mandate에 반하지 않는 순수 결함 교정이다.
3. **가이드를 유입·정보구조의 중심으로 승격** — 원안이 빠뜨렸던 "가이드가 본체"라는 정의를 실제 URL 구조로 구현했다. 이는 mandate C를 약화시키는 절충이 아니라, mandate가 원래 요구했던 것을 뒤늦게 이행한 것이다.

그럼에도 **유지보수 부담(약 8.7h, 8h 기준 초과)은 완전히 해소되지 않는다.** 이는 조항 번호·시행일의 수작업 검증이 mandate C의 목적함수에서 필연적으로 발생하는 비용이기 때문이며, 이 비용을 없애려면 mandate 자체를 버려야 한다. 이 잔여 실패를 숨기지 않고 그대로 남긴다 — 4단계에서 다른 안과 비교할 때 이 비용을 감수할지 여부가 실제 판단 지점이 되어야 한다.
