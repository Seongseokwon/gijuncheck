# 방향 A 반론/수정 — 3단계 반론 라운드 (1회)

원안(`01-direction-a.md`)에 대한 법적/접근성/유지보수/유입 4개 비평을 검토했다. mandate A(T0 최적화 — 판정 도구, 목적함수: 검색 유입 사용자가 클릭·스크롤 최소로 단정적 결론에 도달하는 시간의 최소화)는 유지한다. 아래는 카테고리별 받아들임/거부함이다.

---

## 1. 법적 리스크 비평 — 종합 "높음"

### 받아들임 (부분)

**#2 (면책 위치·크기), #3 (근거 기본 접힘으로 기준연도 확인 불가)를 받아들인다.** 단, #1(단정형 문구 자체를 조건부 문장으로 완전히 바꾸라는 codex 요구)은 전면 수용하지 않고 아래처럼 절충한다 — 이 절충의 논리는 "헤드라인의 단정성을 유지해도 목적함수가 훼손되지 않는 범위 안에서만 법적 방어선을 추가한다"는 것이다.

**구체적 변경:**

- 결과 헤드라인(40px bold "인정됩니다." / "탈락합니다.")은 **그대로 유지한다.** 이것까지 조건부 문장으로 바꾸면 "곁눈질만으로 인지되는 결론"이라는 목적함수 핵심 장치가 무너진다.
- 대신 헤드라인 바로 아래, **같은 최초 뷰포트 안에(추가 스크롤 없이)** 15px regular, 색상 `#0A0A0A`(신규 색상 도입 없음 — 기존 기본 텍스트 색 재사용)로 다음 문장을 **항상 노출**한다(더 이상 힌트 접힘/12px 푸터에 숨기지 않는다):
  > "2026년 기준 계산 결과이며, 최종 판정은 국민건강보험공단 심사에 따라 다를 수 있습니다. **근거 보기**"
- "근거 보기"는 인라인 텍스트 링크로, 클릭 시 기존에 접혀 있던 근거 조항·계산 과정 패널이 그 자리에서 펼쳐진다(페이지 이동 없음, 스텝 추가 없음 — 목적함수의 "클릭 최소화"는 그대로 유지. 이 클릭은 필수 경로가 아니라 선택적 검증 경로다).
- 전역 푸터의 면책 문구(운영자 정보, 사업자 표기 등 사이트 공통 법적 고지)는 위치는 유지하되 크기만 12px → **14px**로 올린다 (접근성 최소 기준과 동시 해결, 아래 2절 참조).
- 입력 화면 최상단(입력 필드보다 위)에 14px medium, `#0A0A0A`로 다음 한 줄을 고정 노출한다: **"민간 참고용 도구 · 공식 판정 아님"**. 이는 codex가 요구한 "운영·검토 주체" 전체 블록이 아니라 최소 1줄로 압축한 것이다.

**거부함 (부분):**

codex가 요구한 "마지막 검토일(lastChecked)"과 "공식 근거 링크(법제처 외부 링크)"를 결과 화면·랜딩 화면에 별도 필드로 추가하는 것은 **거부한다.** 이유: 이 두 요소는 정확성·추적가능성을 전면에 세우는 것이 목적함수인 방향(레퍼런스형)의 장치이지, "가장 빠르게 결론에 도달"이 목적함수인 이 안에는 맞지 않는다. 또한 4절 유지보수 대응에서 보듯 lastChecked 같은 날짜 필드를 새로 만들면 "값이 안 바뀌어도 날짜만 갱신해야 하는 상시 부담"이 발생하는데, 이는 이 안이 스스로 지켜야 할 "판정기 1개 + 가이드 6편만 갱신"이라는 좁은 갱신 범위 원칙과 정면으로 충돌한다. 대신 위에서 추가한 안내문은 **이미 존재하는 DISCLAIMER 상수 문자열을 재사용**하고 새 조항 링크·새 날짜 필드를 만들지 않는다.

## 2. 접근성 비평 — 종합 "실패"

**전부 받아들인다.** 이 지적들은 mandate A의 목적함수와 충돌하지 않는다 — 오히려 목적함수 자체("빠르게 결론에 도달")의 관점에서 보면, 입력 테두리가 안 보이거나 탭 영역이 작아 오탭이 나는 것은 결론 도달 시간을 늘리는 마찰이므로 접근성 결함은 이 mandate 안에서도 결함이다.

**구체적 변경:**

| 항목 | 원안 | 수정값 | 근거 |
|---|---|---|---|
| 입력 테두리 색 | `#D1D5DB` (1.47:1, 실패) | **`#6B7280`** (기존 보조/힌트 텍스트 색 재사용, 대비 4.83:1) | 새 색을 추가하지 않고 이미 팔레트에 있는 값을 재사용해 "색 의미 학습 비용 최소화" 원칙과 충돌 없이 3:1 기준 충족 |
| 접힌 설명·힌트 | 13px | **14px** | 보조설명 최소 기준. 접혀 있다가 사용자가 스스로 펼친 순간에는 반드시 읽혀야 하므로 접힘 여부와 무관하게 최소 크기는 지켜야 한다 |
| 푸터/면책 | 12px | **14px** | 위와 동일 논리 + 1절 법적 수정과 동시 해결 |
| 입력 필드 실제 텍스트 크기 | 명시 없음 | **16px** (신규 명시) | 16px 미만이면 iOS Safari에서 포커스 시 자동 확대되어 화면이 틀어지고 결과적으로 재입력 시간이 늘어난다 — 목적함수 직접 침해이므로 명시 |
| "한 줄 요약 이유" 텍스트 | 명시 없음 | **16px regular** (신규 명시) | 본문 최소 기준 |
| "?" 힌트 아이콘 탭 영역 | 명시 없음 | **44×44px** (신규 명시, 아이콘 시각 크기는 20px 유지하고 패딩으로 히트 영역 확보) | 오탭은 재시도 시간을 유발해 목적함수를 직접 침해한다 |
| "해당사항 있음" 토글 | 명시 없음 | **height 44px** (신규 명시) | 동일 논리 |
| 제출 버튼 | height 48px, width 미기재 | **width: 모바일 100%(패딩 16px 제외), 데스크톱 min 280px** (신규 명시) | 동일 논리 |
| 홈 CTA 버튼 | 명시 없음 | **height 48px, width 동일 규칙** (신규 명시) | 동일 논리 |
| 하단 고정 제출 버튼 세이프에어리어 | 명시 없음 | **`padding-bottom: max(16px, env(safe-area-inset-bottom))`** (신규 명시) | 홈 인디케이터에 가려 오탭·재탭 유발 방지 |

거부 항목 없음 — 이 카테고리는 목적함수와 충돌하는 지적이 하나도 없었다.

## 3. 유지보수 비평 — 종합 "위험" (임계 근접, codex 반영판 7.5h)

### 받아들임

비평이 지적한 핵심은 "codex 수정판을 그대로 반영하면 임계값(8h)에 0.5h 여유밖에 안 남는다"는 것이다. **이걸 받아들이되, 해결 방식은 codex의 요구를 축소 수용하는 것이다** (1절에서 이미 명시).

- lastChecked 날짜 필드, 외부 법제처 링크 등 **신규 메타데이터 필드를 만들지 않음**으로써 codex 반영판이 추가하려던 "기준연도 표시 지점 +1(5곳)" 중 날짜·링크 관련 항목을 제거한다.
- 새로 추가한 고정 안내문("2026년 기준 계산 결과이며...")은 **이미 존재하는 `constants/2026.ts`의 `DISCLAIMER` 상수를 그대로 렌더링**하며 별도 리터럴을 만들지 않는다. 따라서 갱신 지점은 "기준연도 표시 지점"에 렌더링 위치 1곳이 추가될 뿐, leaf 값이나 화면 문구 개수는 늘지 않는다.
- "민간 참고용 도구 · 공식 판정 아님" 문구는 연도·수치를 포함하지 않는 정적 문구이므로 연 1회 갱신 대상에서 아예 제외된다.
- 재산정 결과: 원안(6.5h) 대비 순증 공수는 **QA 시간 +0.3h 내외**(새 안내문 렌더링·링크 동작 확인)로 추정하며, **연간 공수는 약 6.8h로 8h 임계값 아래에 여유를 확보한다.** codex 반영판(7.5h)보다 오히려 유지보수 부담이 줄어든다.

### 거부함

비평이 부수적으로 언급한 "자동 만료 경고·CI 체크 부재(00-brief D-1)"는 **디자인 방향 문서의 스코프 밖이므로 이 라운드에서 다루지 않는다.** 이는 시각 체계·정보 구조의 문제가 아니라 빌드 파이프라인/운영 프로세스의 문제이며, mandate A가 다루는 "화면 설계"로 해결할 수 있는 종류의 리스크가 아니다. 잔여 리스크로 인정하되 이 문서에서 해소를 시도하지 않는다.

## 4. 유입 비평 — 종합 "조건부" (결정적 결함: 도구 페이지에 정체성·신뢰 신호 없음)

### 받아들임

비평의 결정적 결함 지적 — "도구 페이지 단독 진입을 랜딩 기본값으로 못박았으면서 정작 도구 페이지 자체에는 서비스 정체성·신뢰 신호가 없다" — 는 **정확한 지적이며 mandate A와 충돌하지 않는다.** 신뢰 신호 부재는 사용자가 결과를 의심해 재검색·이탈하게 만들어 오히려 "결론 도달"을 완결시키지 못하므로 목적함수를 훼손한다.

**구체적 변경:**

- 1절에서 이미 추가한 "민간 참고용 도구 · 공식 판정 아님" 한 줄(14px medium, 입력 화면 최상단)이 이 역할을 겸한다 — 별도 블록을 새로 만들지 않고 법적 수정과 통합해 화면 분량 증가를 최소화한다.
- **결과 공유 진입 취약성도 받아들인다.** 결과 화면에 입력값 요약 한 줄을 헤드라인과 새 고정 안내문 사이에 추가한다: 예) "입력 기준: 연소득 000만원 · 재산과세표준 000만원". 이 문구는 사용자가 실제 입력한 값을 그대로 반영하는 동적 텍스트이므로 별도 상수·연 1회 갱신 대상이 아니다(3절 유지보수 부담에 영향 없음). 이로써 캡처·공유 시에도 어떤 조건에서 나온 결론인지 맥락이 함께 전달된다.

### 거부함

**"브랜드 검색 유입 시 서비스 전체상을 못 보여준다"는 지적은 거부한다.** 이는 원안 9절에 이미 실패 조건으로 명시된 리스크이며, 이를 해소하려면 홈 설계 분량을 늘려야 하는데 이는 mandate A가 명시적으로 포기한 가치("홈 화면의 서비스 전체상 전달력", 8절)를 되살리는 것이다. mandate A는 "지금 쓰지도 못할 구조를 미리 세우느라 런치 완성도를 깎지 않는다"는 규율을 갖고 있고, 브랜드 검색 사용자를 위한 홈 확장은 정확히 그 규율이 금지하는 종류의 투자다. 이 리스크는 실패 조건으로 남겨두고 감수한다.

## 5. 수정 반영 요약 (원안 대비 diff)

**6절 색상 변경:**
- 입력 테두리: `#D1D5DB` → `#6B7280`

**6절 타이포 스케일 변경:**
- 접힌 설명·힌트: 13px → 14px
- 푸터/면책: 12px → 14px
- 신규: 입력 필드 텍스트 16px, 결과 화면 요약 이유 16px, 신규 고정 안내문 15px, 입력값 요약 15px

**6절 터치 타겟 신규 명시:**
- "?" 아이콘 44×44px, 토글 44px, 제출/CTA 버튼 폭 규칙, 세이프에어리어 패딩

**4절(입력 화면) 추가:**
- 최상단 고정 문구 "민간 참고용 도구 · 공식 판정 아님" (14px medium)

**5절(결과 화면) 추가:**
- 헤드라인(40px, 문구 불변) → 입력값 요약 1줄(15px) → 고정 법적 안내문 1줄(15px, "근거 보기" 링크 포함) → 그 아래 기존 접힌 근거 패널(불변)

**8절(포기한 것) 갱신:**
- "오판정에 대한 완충" 항목을 **부분 완화**로 수정: 헤드라인 자체는 여전히 단정형이지만, 최초 뷰포트 안에 항상 보이는 법적 조건 문구를 추가해 완충을 일부 회복했다. 다만 헤드라인의 시각적 지배력(40px bold vs 15px regular)이 여전히 압도적이므로 완충 효과는 제한적이라는 점은 그대로 인정한다.

**9절(실패 조건) 불변** — 3개 조건 그대로 유지. 브랜드 검색 유입 문제와 국민연금·고용보험 확장 시 재설계 필요성은 여전히 이 안이 안고 가는 리스크다.
