# 방향 B 반론/수정 (3단계 반론 라운드, 1회)

mandate B(T+N 최적화 — 사대보험 허브)는 유지한다. 4영역 구조를 지금 세우고 건강보험만 채운다는 목적함수는 그대로다. 아래 수정은 전부 이 목적함수 **안에서** 문제를 해결하려는 시도이며, 도구 1개로 축소하거나 홈에서 로드맵을 지우는 방향(=사실상 mandate A)으로는 이동하지 않는다.

## 1. 법적 리스크 판정(치명) — 받아들임, 정면 대응

### 3절 vs 5절 모순 — 반드시 다뤄야 하는 지점

법적 비평의 지적은 정확하다. 원안 3절("검증 중 배지가 붙은 **비활성** 카드")과 5절("클릭은 가능하되 상단에 미검증 경고")은 같은 도구(지역보험료 계산기)의 같은 시점 접근 가능성을 서로 다르게 서술했고, 이는 문서 내부 모순인 동시에 Brief가 이미 "치명"으로 지목한 패턴(`ReferenceOnlyNotice` 배지로 완화만 하고 비공개 원칙은 적용 안 됨)을 결과 화면 경로로 재도입한 것이다.

**해소 방식**: mandate B를 유지하면서 이 모순을 없애는 유일한 방법은 "경고 배지 + 클릭 가능"이라는 절충 상태 자체를 삭제하는 것이다. 지역보험료 계산기·임의계속가입 비교는 **서비스의 어느 화면에서도 링크가 되지 않는다.** 홈에서도, 결과 화면 교차링크에서도, 헤더 내비게이션에서도 `href`를 갖지 않는다. 공단 대조 완료(`VERIFIED_AGAINST_NHIS = true`) 전까지는 텍스트로만 존재한다.

- **5절 수정**: "다음 행동 제시 방식"에서 지역보험료 계산·임의계속가입 비교 링크를 완전히 삭제한다. 미충족 시 다음 행동은 관련 가이드(예: "지역가입자 전환 시 무엇이 달라지나" 가이드 문서)로만 연결한다. 계산 도구로의 경로는 이 도구들이 공개되기 전까지 결과 화면 어디에도 없다.
- **3절 수정**: 준비 중 도구는 "카드"가 아니라 도메인 섹션 헤더 옆의 **인라인 텍스트 캡션**으로 격하한다(6절에서 구체 명시). 카드 컴포넌트(패딩·테두리·radius·hover)를 아예 부여하지 않아 "클릭해볼 수 있을 것 같은" 어포던스 자체를 제거한다.

이로써 "같은 도구가 홈에서는 막혀 있고 결과 화면에서는 뚫려 있다"는 상황은 구조적으로 발생할 수 없다 — 뚫린 경로가 애초에 없기 때문이다.

**받아들이는 대가**: mandate B의 분자("판정 결과에서 멈추지 않고 이어지는 이동 경로 수")가 재산요건 미충족 사용자에게는 실제로 줄어든다. 지역보험료라는 가장 직접적인 다음 질문에 대한 답을 이 안은 더 이상 제공하지 못한다. 법적 안전성이 이 mandate의 핵심 지표보다 우선한다고 판단해 받아들인다.

### 항목 2 (미검증 재산점수표 캐비어트) — 받아들임

원안 5절 충족 예시의 "재산 부과점수 산정 기준(무재산 시 1등급 적용)은 공단 대조 전 참고용입니다" 문구를 삭제한다. Brief에 따르면 `judge.ts`는 60등급 부과점수표를 참조하지 않고 재산 문턱값(`SAFE_LIMIT`)만 쓰므로, 이 문구는 실제 계산과 무관한 캐비어트였다. 수정된 문구:

> "현재 입력하신 내용 기준으로는 부양·소득·재산 요건을 모두 충족하는 것으로 판단됩니다."

불필요한 캐비어트를 붙이지 않는 것 자체가 정확성이다.

### 항목 3 (서비스명·도메인 지도 구조로 인한 공식 포털 오인) — 받아들임(경량 조치)

헤더에 상시 노출되는 한 줄을 추가한다: "민간이 운영하는 정보 제공 서비스이며 국민건강보험공단 등 공식 기관이 아닙니다." 이는 5절 결론 문구의 헤징과 별개로, 서비스 정체성 자체에 대한 오인을 막는 장치다. mandate B가 3영역 지도 구조를 포기할 이유는 없지만(그것이 이 안의 존재 이유다), 그 구조가 유발하는 오인 리스크는 별도 문구로 상쇄한다.

### 항목 4 ("검증 중" 라벨의 리스크 전달 실패) — 받아들임(2번 항 구조 변경으로 해소)

아래 6절 수정에서 빌드상태를 3단계(이용가능/검증중/준비중)에서 **2단계(이용가능/준비중)**로 축소한다. "검증 중"이라는 애매한 중간 상태 자체를 없애므로, 이 라벨이 리스크를 제대로 전달하는지 여부를 따질 필요가 없어진다 — 애초에 클릭할 수 없는 상태에는 라벨의 설득력이 중요하지 않다.

## 3. 유지보수 판정(실패, 연 10.5h) — 받아들임, 구조 자체를 절삭

codex 피드백이 제안한 "축소형 B"(단일 활성 도구 + 상태 플래그로 나중에 동시 오픈)로는 유지보수 비평이 지적한 대로 8~9h로 여전히 경계를 넘는다. 이유는 그 안이 "라우트는 존재하되 플래그로 잠근다"는 패턴을 유지하기 때문이다 — 잠긴 라우트도 회귀 테스트·상태 동기화 대상이다.

이 안은 codex보다 한 단계 더 나아간다: **지역보험료·임의계속가입은 코드 레벨에서 UI에 연결된 라우트를 아예 갖지 않는다.** 준비 중 항목은 도메인 섹션 헤더 옆의 정적 텍스트 캡션 하나이며, 뒤에 컴포넌트도 상태 플래그도 없다. 공단 대조가 끝나면 그때 라우트를 새로 만든다 — "미리 지어놓고 잠가둔다"가 아니라 "짓지 않는다."

### 재산정된 갱신 표면적

| 항목 | 원안 | 수정 | 사유 |
|---|---|---|---|
| 빌드상태 조합 | 3단계(이용가능/검증중/준비중) | **2단계**(이용가능/준비중) | "검증 중" 삭제로 상태 조합 수(상태×결과유형) 9→6, 곱셈 증가 계수 감소 |
| 결과화면 교차링크 목적지 | 3곳(지역보험료·임의계속가입·가이드) | **1곳**(가이드만) | 미검증 도구로의 추천 로직 자체가 사라짐 — "결과유형별 교차링크 추천 로직 3곳"이 사실상 1곳으로 축소 |
| 준비중 표시 컴포넌트 | 카드(패딩·테두리·radius·상태별 스타일) | 인라인 텍스트 1줄 | 카드별 스타일·hover·상태 동기화 유지보수가 사라짐 |
| 교차링크 설정 | 화면별 개별 하드코딩(암묵) | 단일 `crossLinkConfig` 소스 | 원안 7절이 이미 인지한 "단일 소스 필요"를 이번에 실제로 구조에 반영 |

### 재산정된 연간 공수

| 작업 | 원안 | 수정 | 사유 |
|---|---|---:|---|
| 개정 내용 파악·확인 | 2h | 1.5h | 준비중 도구가 UI·라우트에 없으므로 매년 "이 수치가 여전히 화면에 안전하게 노출되는지" 점검할 대상 자체가 줄어듦 |
| 코드 상수 수정 | 1h | 1h | 동일(2026.ts 갱신은 mandate와 무관하게 필요) |
| 화면 문구 수정 | 3h | 1.5h | 교차링크 목적지 3→1, 빌드상태 배지 3→2 |
| 검증·회귀 테스트 | 2.5h | 1.5h | 클릭 가능한 미검증 경로가 없어 회귀 테스트 범위가 활성 도구 1개 + 홈 카드 상태 표시로 축소 |
| 가이드 6편 문구 갱신 | 2h | 2h | 동일(mandate와 무관, 콘텐츠 볼륨의 함수) |
| **합계** | **10.5h** | **7.5h** | |

**정직한 한계**: 이 7.5h는 구조 절삭에 따른 재추정이며 감사받은 수치가 아니다. 다중 도메인·다중 상태를 다루는 한 단일 도구 서비스보다 유지보수 공수가 구조적으로 높다는 사실 자체는 사라지지 않는다(원안 8절이 이미 인정한 대가). 이번 수정은 "8h를 넘지 않게 최대한 깎았다"는 것이지 "다중 도메인의 대가가 없어졌다"는 뜻이 아니다. 실측 결과 이 추정을 넘으면 이 안은 폐기 대상이 된다(9절 실패조건에 추가되어야 할 항목).

## 4. 유입 판정(조건부) — 부분 받아들임

결정적 결함은 아니라고 비평 스스로 밝혔으므로 구조 전체를 뒤집지는 않는다. 다만 두 가지는 수정한다.

**받아들임 1 — 헤더가 정체성을 더 많이 들고 가도록 강화**: 원래 헤더 내비게이션은 "얇은 바" 정도로만 명시되어, 시나리오 1(검색 직접 진입)에서 홈의 대형 자산 대부분이 도달하지 않는다는 지적이 타당했다. 헤더에 도메인 색 점(●) + 라벨 3개를 상시 노출한다(건강보험=활성 링크, 국민연금·고용보험=회색 텍스트, 링크 없음). 이는 홈을 키우지 않으면서 모든 페이지에 "이곳은 3영역 허브다"라는 신호를 옮기는 저비용 조치다.

**받아들임 2 — 준비중 영역의 시각적 비중 축소**: 위 1절·3절 수정(카드→인라인 텍스트 캡션)으로 "미완성 서비스"라는 인상을 주는 빈 카드 문제가 함께 완화된다. 이는 원래 acq 비평이 지적한 문제와 codex 피드백("준비 중 영역을 홈 핵심 자산으로 만들지 않는다")을 동시에 만족시키는 결과다.

**거부함 — 홈 설계 분량 자체를 줄이라는 요구**: 상황 기반 진입 라우터와 3도메인 섹션 헤더는 유지한다. mandate B의 핵심은 "서비스명이 약속한 범위를 화면 구조로 먼저 구현하는 것"이며, 홈이 자주 랜딩되지 않는다는 사실이 홈의 지도 기능 자체를 없앨 이유는 아니다. acq 비평도 "홈 경유 시나리오는 성립한다"고 인정했다 — 문제는 투자와 확률의 불균형이지 홈 구조의 무용성이 아니다. 헤더 강화로 시나리오 1의 손실을 일부 상쇄했으므로, 홈 자체를 얇게 만드는 것까지는 받아들이지 않는다.

## 6. 결론

법적 모순(3절 vs 5절)은 "미검증 도구는 어디서도 링크가 되지 않는다"는 단일 규칙으로 해소했다. 접근성 실패는 색상·크기 재조정과 티어 통합으로 해소했다. 유지보수 실패는 codex의 "축소형" 제안보다 더 급진적인 절삭(라우트 자체를 만들지 않음)으로 대응했으며, 그 결과로도 7.5h는 재추정치일 뿐 보장이 아니라는 점을 명시했다. 유입 비평은 결정적 결함이 아니므로 부분 수용했고, 홈 지도 구조 자체를 줄이라는 요구는 mandate B의 목적함수와 직접 충돌하므로 거부했다.
