## 1. 프로젝트 개요

### 이름

| 항목 | 값 |
|---|---|
| 프로젝트 · 저장소명 | **sabohum** |
| 서비스명 (한글) | **사대보험** |
| 도메인 1안 | **사대보험.kr** |
| 도메인 대안 | 내사회보험.kr · 보험료연구소.kr · sabohum.kr |

**왜 이 이름인가**

4대보험(건강보험·국민연금·고용보험·산재보험)은 계획된 도구 세 개를 모두 담는 우산입니다.

- 피부양자 판정 → 건강보험
- 국민연금 조기·연기수령 → 국민연금
- 육아휴직급여 → 고용보험

**이름에 시간을 쓰지 마세요.** 도메인은 연 2만원이고 언제든 바꿀 수 있습니다. SEO를 실제로 결정하는 건 URL 경로와 콘텐츠입니다. 한 시간 안에 정하고 넘어가면 됩니다.

### 한 줄 정의

> 소득이 바뀔 때 내 사회보험이 어떻게 바뀌는지 **판정**해주는 도구.

경쟁 사이트는 전부 "계산"만 합니다. 우리는 **판정**합니다. 이게 유일한 차별점이고, 이 문서의 나머지는 전부 이 문장을 지키기 위한 설계입니다.

## 2. 목표와 성공 지표

수익이 아니라 **선행지표**를 봅니다. 수익은 6개월 뒤에나 의미 있는 숫자가 나옵니다.

| 시점 | 선행지표 | 수익 (참고) |
|---|---|---|
| 2주 | 판정기 v1 배포, 실제 URL 존재 | — |
| 6주 | 해설 6편 발행, 색인 등록 확인 | — |
| 8주 | 애드센스 승인 | — |
| 3개월 | 월 5,000 PV, 타겟 키워드 3개 2페이지 진입 | 월 2~5만원 |
| 6개월 | 월 1만 PV, 주 키워드 1개 1페이지 | 월 8~15만원 |
| 12개월 | 월 5만 PV | 월 40~60만원 |
| 18개월 | 월 15만 PV | 월 120~180만원 |

### 수익 추정의 전제 (중요)

RPM을 보수적으로 **8,000원**으로 잡았습니다. 리서치의 카테고리 RPM은 10,000~30,000원이지만, 그건 **콘텐츠 페이지** 기준입니다.

> **도구 페이지는 RPM이 낮습니다.** 답을 얻고 즉시 이탈하기 때문에 노출이 적고 체류시간이 짧습니다.

그래서 해설 콘텐츠는 애드센스 승인용만이 아니라 **RPM 방어용**입니다. 도구 → 해설로 이어지는 내부 동선이 실제 수익을 만듭니다. 이 설계를 빼면 추정치의 절반도 안 나옵니다.

## 4. 정보 구조 (URL 설계)

SEO에서 도메인명보다 중요합니다. **키워드는 경로에 넣습니다.**

```
/                                    허브 — 도구 목록
│
├── /건강보험
│   ├── /피부양자-자격판정              ★ 1순위 도구
│   ├── /지역가입자-보험료계산          ★ 2단
│   ├── /임의계속가입-비교              ★ 3단
│   └── /가이드
│       ├── /재산세-과세표준-확인방법
│       ├── /피부양자-자격상실-시점
│       ├── /임의계속가입-유리한경우
│       ├── /사업자등록-전-확인사항
│       ├── /연금수령과-피부양자
│       └── /11월-자격재산정
│
├── /국민연금                          3순위 (3~4개월)
│   └── /조기수령-연기수령-비교
│
└── /고용보험                          2순위 (6개월+)
    └── /육아휴직급여-계산
```

### 규칙

1. **한글 경로를 씁니다.** 네이버 색인에서 유리하고, 사용자가 URL만 봐도 내용을 압니다. Next.js는 한글 경로를 정상 처리합니다.
2. **도구 1개 = 페이지 1개.** 탭으로 묶으면 각 키워드의 랜딩이 사라집니다.
3. **모든 도구 페이지 하단에 관련 가이드 3개를 링크합니다.** RPM 방어 동선.
4. **가이드 본문에서 도구를 링크합니다.** 양방향 내부 링크.

## 5. 핵심 기능 스펙

### 5.1 피부양자 자격 판정기 (1순위)

3단 판정을 순차 통과해야 자격이 인정됩니다. 하나라도 걸리면 그 지점에서 탈락 이유를 명시합니다.

```
[입력]
  관계 / 동거여부 / 나이 / 혼인여부 / 장애여부
  소득: 사업·근로·연금·금융·기타 (연간)
  사업자등록 여부
  재산세 과세표준
        ↓
[1단] 부양요건 — 관계가 인정 범위인가
        ↓ 통과
[2단] 소득요건 — 합산 2,000만원 + 사업소득 특례
        ↓ 통과
[3단] 재산요건 — 과표 구간별 판정
        ↓ 통과
[결과] 자격 인정 / 탈락 (+ 탈락 사유와 근거 조항)
        ↓ 탈락한 경우
[연결] 지역가입자 보험료 자동 계산 → 임의계속가입 비교
```

**UX 원칙**

- 입력은 한 화면. 단계별 위저드로 쪼개면 이탈합니다.
- 결과는 즉시 계산 (서버 왕복 없음). 전부 클라이언트 순수 함수.
- 결과에 **근거 조항과 기준 연도**를 항상 표시. 신뢰가 이 사이트의 전부입니다.
- 탈락 시 "그래서 얼마 내야 하나"로 바로 이어지는 CTA. 여기서 세션이 길어집니다.

**반드시 넣을 면책 문구**

> 본 판정은 모의 결과이며 법적 효력이 없습니다. 최종 확인은 국민건강보험공단(1577-1000)에 문의하시기 바랍니다. 기준: 2026년.

### 5.2 지역가입자 보험료 계산 (2단)

```
소득월액 = 연간 합산소득 ÷ 12
건강보험료 = (소득월액 × 7.19%) + (재산보험료부과점수 × 211.5원)
장기요양보험료 = 건강보험료 × (0.9448 ÷ 7.19)
총 보험료 = 건강보험료 + 장기요양보험료
```

> **미완성 영역 — 재산보험료부과점수 등급표**
> 재산세 과세표준을 점수로 바꾸는 60등급 고시표가 필요합니다. 공단 고시 원문을 확인해 `src/lib/constants/property-score-table.ts`에 입력해야 합니다. 현재는 근사 구간표가 들어가 있고 코드에 `TODO(verify)`로 표시했습니다. **이 표를 확정하기 전에는 보험료 계산 페이지를 공개하지 마세요.** 틀린 금액은 판정 오류보다 신뢰 타격이 큽니다.

### 5.3 임의계속가입 비교 (3단)

여기가 아무도 안 하는 영역이고, 사용자에게 가장 실질적인 가치입니다.

| 항목 | 임의계속가입 | 지역가입자 |
|---|---|---|
| 산정 기준 | 퇴직 전 12개월 보수월액 평균 | 소득 + **재산 + 자동차** |
| 재산 반영 | 없음 | 있음 |
| 기간 | 최대 36개월 | 무제한 |
| 피부양자 등재 | 가능 | 불가 |
| 신청 조건 | 퇴직 전 18개월 중 직장가입 통산 1년 이상 | — |

**결론 로직**: 재산이 많고 퇴직 전 보수가 낮았으면 임의계속가입이 유리. 두 금액을 계산해 유리한 쪽을 굵게 표시합니다.

**놓치면 안 되는 안내**: 퇴직 후 **90일 이내** 신고 시 퇴사일로 소급 인정됩니다. 이 한 줄이 사용자에게 실제로 돈을 아껴주고, 공유를 유발합니다.

## 6. 판정 요건 데이터 (2026년 · 검증됨)

구현에 직접 쓰이는 값입니다. 모두 `src/lib/constants/2026.ts`에 있습니다.

### 6.1 부양요건 (관계별)

| 관계 | 동거 시 | 비동거 시 |
|---|---|---|
| 배우자 | 인정 | 인정 |
| 직계존속 (부모·조부모) | 인정 | 동거 형제자매가 없거나, 있어도 소득이 없으면 인정 |
| 직계비속 (자녀·손자녀) | 인정 | 미혼이면 인정 |
| 배우자의 직계존속 | 인정 | 직계존속과 동일 |
| 배우자의 직계비속 | 인정 | 미혼이면 인정 |
| 형제자매 | 만 30세 미만 또는 만 65세 이상 또는 장애인 + **미혼**일 때만 인정 | 원칙 불인정 |

### 6.2 소득요건

| 조건 | 기준 |
|---|---|
| 합산소득 | 연 **2,000만원 이하** (사업·근로·공적연금·금융·기타 합산) |
| 사업자등록 **있음** | 사업소득이 **0원**이어야 인정 (1원이라도 있으면 탈락) |
| 사업자등록 **없음** | 사업소득 연 **500만원 이하** |
| 장애인·국가유공상이자 | 사업자등록 있어도 사업소득 500만원 이하면 인정 |

> 2,000만 1원도 초과 시 탈락입니다. 월 기준이 아니라 **연 합산** 기준입니다.

### 6.3 재산요건 (재산세 **과세표준** 기준)

| 과표 구간 | 판정 |
|---|---|
| 5.4억 이하 | 인정 |
| 5.4억 초과 ~ 9억 이하 | 연소득 **1,000만원 이하**면 인정 |
| 9억 초과 | 소득 0원이어도 **탈락** |
| 형제자매 | **1.8억 이하** (일반보다 엄격) |

> 실거래가·공시가격이 아니라 **재산세 과세표준**입니다. 공시가격 10억 ≈ 과표 약 6억.
> 이 환산을 헷갈리는 사람이 많아 가이드 글 1편을 여기에 배정했습니다.

## 7. SEO 설계

### 7.1 페이지별 메타

도구 페이지 title 패턴: `{키워드} — {차별점} | 사대보험`

```
피부양자 자격판정 — 소득·재산·관계 3단 자동 판정 | 사대보험
지역가입자 보험료 계산 — 2026년 요율 7.19% 반영 | 사대보험
```

description에는 **숫자를 넣습니다.** "2,000만원", "2026년", "7.19%" 같은 구체값이 클릭률을 올립니다.

### 7.2 구조화 데이터 (JSON-LD)

- 도구 페이지: `WebApplication` + `FAQPage`
- 가이드 페이지: `Article` + `FAQPage`

FAQPage는 검색 결과에서 자리를 넓게 먹습니다. 페이지마다 FAQ 3~5개는 필수입니다.

### 7.3 기술 SEO 체크리스트

- [ ] 전 페이지 SSG (`generateStaticParams`) — 도구도 정적 발행, 계산은 클라이언트
- [ ] `sitemap.ts` 자동 생성
- [ ] `robots.ts`
- [ ] canonical 태그
- [ ] 네이버 서치어드바이저 + 구글 서치콘솔 등록
- [ ] LCP 2.5초 이내 (도구 사이트는 여기서 이깁니다 — 경쟁자들이 다 느립니다)
- [ ] 모바일 우선. 트래픽 70% 이상이 모바일입니다.

### 7.4 콘텐츠 캘린더 (6주 · 주 1편)

| 주 | 글 | 타겟 키워드 |
|---|---|---|
| 1 | 재산세 과세표준 확인하는 방법 | 재산세 과세표준 조회 |
| 2 | 사업자등록 전에 반드시 계산해야 하는 것 | 사업자등록 피부양자 |
| 3 | 피부양자 자격상실 시점과 소급 부과 | 피부양자 자격상실 |
| 4 | 임의계속가입이 유리한 경우 | 임의계속가입 |
| 5 | 연금 수령이 피부양자 자격에 미치는 영향 | 연금소득 피부양자 |
| 6 | 11월 자격 일괄 재산정이란 | 피부양자 재산정 |

각 글은 2,000자 이상 + 도구 링크 + FAQ 3개. 짧은 글은 애드센스 승인에 불리합니다.

## 8. 수익화 설계

### 8.1 애드센스 승인 전략

계산기만 있는 사이트는 **"가치 없는 콘텐츠"로 거절되는 사례가 많습니다.** 순서를 지키세요.

1. 도구 3개 + 가이드 6편 발행 **후에** 신청 (도구만으로 신청 금지)
2. 필수 페이지: 개인정보처리방침, 이용약관(면책), 문의
3. 서치콘솔 색인 완료 확인 후 신청
4. 거절 시 콘텐츠 3편 추가 후 재신청

### 8.2 광고 배치

| 위치 | 형태 | 비고 |
|---|---|---|
| 판정 결과 **직후** | 디스플레이 | 최고 성과 구간. 답을 본 직후 |
| 가이드 본문 중간 | 인아티클 | RPM 주력 |
| 사이드바 (데스크톱) | 디스플레이 | — |
| 도구 **입력 폼 위** | ❌ 금지 | 이탈률 급증 |

> 자동광고는 초기에 끄세요. 폼 안에 광고가 박혀서 도구를 망칩니다. 수동 배치로 시작합니다.

### 8.3 애드센스 이후

## 9. 기술 아키텍처

```
Next.js 15 (App Router) + TypeScript + Tailwind
        ↓
전 페이지 SSG · 서버 런타임 없음
        ↓
Vercel (무료 티어로 충분)
```

### 설계 원칙

**1. 판정·계산 로직은 순수 함수로 완전 분리합니다.**

```
src/lib/
├── constants/
│   ├── 2026.ts                    연도별 요건·요율
│   └── property-score-table.ts    재산점수 등급표 (미확정)
├── dependent/
│   ├── types.ts
│   ├── judge.ts                   판정 로직
│   └── judge.test.ts
└── premium/
    ├── regional.ts                지역보험료
    └── regional.test.ts
```

UI에 로직을 넣지 마세요. 법령이 바뀔 때마다 UI를 뒤져야 합니다.

**2. 연도별 상수를 반드시 분리합니다.**

요건과 요율은 **매년 바뀝니다.** 상수를 코드에 흩뿌리면 1년 뒤 유지보수가 지옥이 되고, 그때 경쟁자에게 밀립니다. 리서치에서 확인한 것처럼 기존 계산기들이 낡아서 죽었습니다.

```ts
// 이렇게
export const RULES_2026 = { healthRate: 0.0719, ... };

// 이러지 말고
const premium = income * 0.0719;
```

**3. 경계값 테스트를 먼저 씁니다.**

2,000만원 ±1원, 과표 5.4억/9억 경계, 형제자매 30세/65세 경계. 이 지점들이 사용자가 실제로 확인하러 오는 곳이고, 틀리면 신뢰를 잃습니다.

## 10. 8주 로드맵

주 20시간 기준입니다.

| 주 | 작업 | 산출물 |
|---|---|---|
| 1 | 도메인 확보, 스캐폴드, 판정 로직 + 테스트 | 로컬에서 판정 동작 |
| 2 | 판정기 UI, 결과 화면, Vercel 배포 | **공개 URL 존재** |
| 3 | 재산점수 등급표 확정, 지역보험료 계산 | 2단 완성 |
| 4 | 임의계속가입 비교, 서치콘솔·서치어드바이저 등록 | 3단 완성, 색인 시작 |
| 5 | 가이드 1~3편 | — |
| 6 | 가이드 4~6편, 정책·약관 페이지 | — |
| 7 | 애드센스 신청, Core Web Vitals 튜닝 | 신청 완료 |
| 8 | 승인 대응, 광고 배치, 순위 모니터링 세팅 | **수익 발생 시작** |

### 2주차가 분기점입니다

**공개 URL이 없으면 그 뒤 전부가 무의미합니다.** 디자인을 다듬고 싶은 충동이 올 텐데, 2주차에는 못생겨도 배포하세요. 색인은 시간이 걸리고, 시계는 배포 시점부터 돕니다.

## 11. 리스크와 대응

| 리스크 | 심각도 | 대응 |
|---|---|---|
| 판정 오류 | **치명** | 경계값 테스트 + 공단 모의계산 10케이스 대조 + 근거 조항 표시 + 면책 문구 |
| 재산점수 등급표 부정확 | **높음** | 고시 원문 확인 전까지 보험료 페이지 미공개 |
| 법령 변경 | 중 | 연도별 상수 분리. 매년 1월·11월 점검을 캘린더에 고정 |
| SEO 지연 (6~12개월) | 중 | 예상된 일. 이 기간 현금은 외주로 |
| 애드센스 거절 | 중 | 도구만으로 신청 금지. 가이드 6편 선행 |
| 공단이 직접 도구 출시 | 낮음 | 우리 강점은 판정+비교+UX. 공단은 이걸 안 합니다 |
| 겸업 규정 저촉 | 낮음 | 선박관리 도메인과 무관. 단 지식재산 귀속 조항은 별도 확인 |

## 12. 유지보수 체계

이 사이트의 경쟁력은 **최신성**입니다. 리서치에서 확인했듯 경쟁자들은 제도 변경을 못 따라가서 틀린 값을 보여주고 있습니다.

| 시점 | 작업 |
|---|---|
| 매년 1월 | 보험료율·요건 개정 반영, 상수 파일 신규 연도 추가 |
| 매년 11월 | 피부양자 자격 일괄 재산정 시기. 트래픽 피크. 콘텐츠 갱신 |
| 분기 | 상위 노출 순위 점검, 경쟁 사이트 신규 진입 확인 |
| 수시 | 법령 개정 뉴스 모니터링 (국민건강보험법 시행규칙) |

각 페이지에 **"기준: 2026년 · 최종 확인 2026-07-30"**을 표시하세요. 사용자 신뢰와 검색 신선도 신호를 동시에 얻습니다.
