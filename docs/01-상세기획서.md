## 1. 프로젝트 개요

### 이름

| 항목 | 값 |
|---|---|
| 프로젝트 · 저장소명 | **sabohum** |
| 서비스명 (한글) | **사대보험** |
| 도메인 1안 | **사대보험.kr** |
| 도메인 대안 | 내사회보험.kr · 보험료연구소.kr · sabohum.kr |

**왜 이 이름인가**

4대보험(건강보험·국민연금·고용보험·산재보험)은 계획된 도구 세 개를 모두 담는 우산입니다.

- 피부양자 판정 → 건강보험
- 국민연금 조기·연기수령 → 국민연금
- 육아휴직급여 → 고용보험

**이름에 시간을 쓰지 마세요.** 도메인은 연 2만원이고 언제든 바꿀 수 있습니다. SEO를 실제로 결정하는 건 URL 경로와 콘텐츠입니다. 한 시간 안에 정하고 넘어가면 됩니다.

### 한 줄 정의

> 퇴직 전후 건강보험 선택을 공식 기준과 공개된 검증 이력으로 설명하는 민간 참고 도구.

경쟁 서비스에도 피부양자·임의계속·지역가입자 비교 기능이 있으므로, 차별점은 판정 기능의
존재 자체가 아니라 정밀한 조건 처리, 공식 근거 연결, 공단 사례 대조, 갱신 이력과 한계
공개에서 만든다. 현재 포지셔닝의 근거와 경쟁 비교는 [실행 우선순위 문서](./04-실행-우선순위.md)를
기준으로 한다.

## 2. 목표와 성공 지표

수익이 아니라 **선행지표**를 봅니다. 수익은 6개월 뒤에나 의미 있는 숫자가 나옵니다.

| 시점 | 선행지표 | 수익 (참고) |
|---|---|---|
| 2주 | 판정기 v1 배포, 실제 URL 존재 | — |
| 6주 | 해설 6편 발행, 색인 등록 확인 | — |
| 8주 | 애드센스 승인 | — |
| 3개월 | 월 5,000 PV, 타겟 키워드 3개 2페이지 진입 | 월 2~5만원 |
| 6개월 | 월 1만 PV, 주 키워드 1개 1페이지 | 월 8~15만원 |
| 12개월 | 월 5만 PV | 월 40~60만원 |
| 18개월 | 월 15만 PV | 월 120~180만원 |

### 수익 추정의 전제 (중요)

RPM을 보수적으로 **8,000원**으로 잡았습니다. 리서치의 카테고리 RPM은 10,000~30,000원이지만, 그건 **콘텐츠 페이지** 기준입니다.

> **도구 페이지는 RPM이 낮습니다.** 답을 얻고 즉시 이탈하기 때문에 노출이 적고 체류시간이 짧습니다.

그래서 해설 콘텐츠는 애드센스 승인용만이 아니라 **RPM 방어용**입니다. 도구 → 해설로 이어지는 내부 동선이 실제 수익을 만듭니다. 이 설계를 빼면 추정치의 절반도 안 나옵니다.

## 4. 정보 구조 (URL 설계)

SEO에서 도메인명보다 중요합니다. **키워드는 경로에 넣습니다.**

```
/                                    허브 — 도구 목록
│
├── /건강보험
│   ├── /피부양자-자격판정              ★ 1순위 도구
│   ├── /지역가입자-보험료계산          ★ 2단
│   ├── /임의계속가입-비교              ★ 3단
│   └── /가이드
│       ├── /재산세-과세표준-확인방법
│       ├── /피부양자-자격상실-시점
│       ├── /임의계속가입-유리한경우
│       ├── /사업자등록-전-확인사항
│       ├── /연금수령과-피부양자
│       └── /11월-자격재산정
│
├── /국민연금                          3순위 (3~4개월)
│   └── /조기수령-연기수령-비교
│
└── /고용보험                          2순위 (6개월+)
    └── /육아휴직급여-계산
```

### 규칙

1. **한글 경로를 씁니다.** 네이버 색인에서 유리하고, 사용자가 URL만 봐도 내용을 압니다. Next.js는 한글 경로를 정상 처리합니다.
2. **도구 1개 = 페이지 1개.** 탭으로 묶으면 각 키워드의 랜딩이 사라집니다.
3. **모든 도구 페이지 하단에 관련 가이드 3개를 링크합니다.** RPM 방어 동선.
4. **가이드 본문에서 도구를 링크합니다.** 양방향 내부 링크.

## 5. 핵심 기능 스펙

### 5.1 피부양자 자격 판정기 (1순위)

3단 판정을 순차 통과해야 자격이 인정됩니다. 하나라도 걸리면 그 지점에서 탈락 이유를 명시합니다.

```
[입력]
  관계 / 동거여부 / 나이 / 혼인여부 / 장애여부
  소득: 사업·근로·연금·금융·기타 (연간)
  사업자등록 여부
  재산세 과세표준
        ↓
[1단] 부양요건 — 관계가 인정 범위인가
        ↓ 통과
[2단] 소득요건 — 합산 2,000만원 + 사업소득 특례
        ↓ 통과
[3단] 재산요건 — 과표 구간별 판정
        ↓ 통과
[결과] 자격 인정 / 탈락 (+ 탈락 사유와 근거 조항)
        ↓ 탈락한 경우
[연결] 지역가입자 보험료 자동 계산 → 임의계속가입 비교
```

**UX 원칙**

- 입력은 한 화면. 단계별 위저드로 쪼개면 이탈합니다.
- 결과는 즉시 계산 (서버 왕복 없음). 전부 클라이언트 순수 함수.
- 결과에 **근거 조항과 기준 연도**를 항상 표시. 신뢰가 이 사이트의 전부입니다.
- 탈락 시 "그래서 얼마 내야 하나"로 바로 이어지는 CTA. 여기서 세션이 길어집니다.

**반드시 넣을 면책 문구**

> 본 판정은 모의 결과이며 법적 효력이 없습니다. 최종 확인은 국민건강보험공단(1577-1000)에 문의하시기 바랍니다. 기준: 2026년.

### 5.2 지역가입자 보험료 계산 (2단)

```
소득월액 = 연간 합산소득 ÷ 12
건강보험료 = (소득월액 × 7.19%) + (재산보험료부과점수 × 211.5원)
장기요양보험료 = 건강보험료 × (0.9448 ÷ 7.19)
총 보험료 = 건강보험료 + 장기요양보험료
```

> **미완성 영역 — 재산보험료부과점수 등급표**
> 재산세 과세표준을 점수로 바꾸는 60등급 고시표가 필요합니다. 공단 고시 원문을 확인해 `src/lib/constants/property-score-table.ts`에 입력해야 합니다. 현재는 근사 구간표가 들어가 있고 코드에 `TODO(verify)`로 표시했습니다. **이 표를 확정하기 전에는 보험료 계산 페이지를 공개하지 마세요.** 틀린 금액은 판정 오류보다 신뢰 타격이 큽니다.

### 5.3 임의계속가입 비교 (3단)

여기가 아무도 안 하는 영역이고, 사용자에게 가장 실질적인 가치입니다.

| 항목 | 임의계속가입 | 지역가입자 |
|---|---|---|
| 산정 기준 | 퇴직 전 12개월 보수월액 평균 | 소득 + **재산 + 자동차** |
| 재산 반영 | 없음 | 있음 |
| 기간 | 최대 36개월 | 무제한 |
| 피부양자 등재 | 가능 | 불가 |
| 신청 조건 | 퇴직 전 18개월 중 직장가입 통산 1년 이상 | — |

**결론 로직**: 재산이 많고 퇴직 전 보수가 낮았으면 임의계속가입이 유리. 두 금액을 계산해 유리한 쪽을 굵게 표시합니다.

**놓치면 안 되는 안내**: 퇴직 후 **90일 이내** 신고 시 퇴사일로 소급 인정됩니다. 이 한 줄이 사용자에게 실제로 돈을 아껴주고, 공유를 유발합니다.

## 6. 판정 요건 데이터 (2026년 · 검증됨)

구현에 직접 쓰이는 값입니다. 모두 `src/lib/constants/2026.ts`에 있습니다.

### 6.1 부양요건 (관계별)

| 관계 | 동거 시 | 비동거 시 |
|---|---|---|
| 배우자 | 인정 | 인정 |
| 직계존속 (부모·조부모) | 인정 | 동거 형제자매가 없거나, 있어도 소득이 없으면 인정 |
| 직계비속 (자녀·손자녀) | 인정 | 미혼이면 인정 |
| 배우자의 직계존속 | 인정 | 직계존속과 동일 |
| 배우자의 직계비속 | 인정 | 미혼이면 인정 |
| 형제자매 | 만 30세 미만 또는 만 65세 이상 또는 장애인 + **미혼**일 때만 인정 | 원칙 불인정 |

### 6.2 소득요건

| 조건 | 기준 |
|---|---|
| 합산소득 | 연 **2,000만원 이하** (사업·근로·공적연금·금융·기타 합산) |
| 사업자등록 **있음** | 사업소득이 **0원**이어야 인정 (1원이라도 있으면 탈락) |
| 사업자등록 **없음** | 사업소득 연 **500만원 이하** |
| 장애인·국가유공상이자 | 사업자등록 있어도 사업소득 500만원 이하면 인정 |

> 2,000만 1원도 초과 시 탈락입니다. 월 기준이 아니라 **연 합산** 기준입니다.

### 6.3 재산요건 (재산세 **과세표준** 기준)

| 과표 구간 | 판정 |
|---|---|
| 5.4억 이하 | 인정 |
| 5.4억 초과 ~ 9억 이하 | 연소득 **1,000만원 이하**면 인정 |
| 9억 초과 | 소득 0원이어도 **탈락** |
| 형제자매 | **1.8억 이하** (일반보다 엄격) |

> 실거래가·공시가격이 아니라 **재산세 과세표준**입니다. 공시가격 10억 ≈ 과표 약 6억.
> 이 환산을 헷갈리는 사람이 많아 가이드 글 1편을 여기에 배정했습니다.

## 7. SEO 설계

### 7.1 페이지별 메타

도구 페이지 title 패턴: `{키워드} — {차별점} | 사대보험`

```
피부양자 자격판정 — 소득·재산·관계 3단 자동 판정 | 사대보험
지역가입자 보험료 계산 — 2026년 요율 7.19% 반영 | 사대보험
```

description에는 **숫자를 넣습니다.** "2,000만원", "2026년", "7.19%" 같은 구체값이 클릭률을 올립니다.

### 7.2 구조화 데이터 (JSON-LD)

- 도구 페이지: `WebApplication` + `FAQPage`
- 가이드 페이지: `Article` + `FAQPage`

FAQPage는 화면에 실제 표시되는 질문·답변을 검색엔진이 이해하도록 돕는 보조 데이터다.
[Google Search Central 공식 안내](https://developers.google.com/search/blog/2023/08/howto-faq-changes)에
따르면 FAQ 리치 결과는 일반 사이트에 정기적으로 노출되지 않으며 표시를 보장하지 않으므로,
검색 결과 면적을 넓히려는 목적으로 FAQ를 추가하지 않는다. 현재 화면에 있는 FAQ만 유지한다.

### 7.3 기술 SEO 체크리스트

- [ ] 전 페이지 SSG (`generateStaticParams`) — 도구도 정적 발행, 계산은 클라이언트
- [ ] `sitemap.ts` 자동 생성
- [ ] `robots.ts`
- [ ] canonical 태그
- [ ] 네이버 서치어드바이저 + 구글 서치콘솔 등록
- [ ] LCP 2.5초 이내 (도구 사이트는 여기서 이깁니다 — 경쟁자들이 다 느립니다)
- [ ] 모바일 우선. 트래픽 70% 이상이 모바일입니다.

### 7.4 콘텐츠 캘린더 (6주 · 주 1편)

| 주 | 글 | 타겟 키워드 |
|---|---|---|
| 1 | 재산세 과세표준 확인하는 방법 | 재산세 과세표준 조회 |
| 2 | 사업자등록 전에 반드시 계산해야 하는 것 | 사업자등록 피부양자 |
| 3 | 피부양자 자격상실 시점과 소급 부과 | 피부양자 자격상실 |
| 4 | 임의계속가입이 유리한 경우 | 임의계속가입 |
| 5 | 연금 수령이 피부양자 자격에 미치는 영향 | 연금소득 피부양자 |
| 6 | 11월 자격 일괄 재산정이란 | 피부양자 재산정 |

각 글은 2,000자 이상 + 도구 링크 + FAQ 3개. 짧은 글은 애드센스 승인에 불리합니다.

## 8. 수익화 설계

### 8.1 애드센스 승인 전략

계산기만 있는 사이트는 **"가치 없는 콘텐츠"로 거절되는 사례가 많습니다.** 순서를 지키세요.

1. 도구 3개 + 가이드 6편 발행 **후에** 신청 (도구만으로 신청 금지)
2. 필수 페이지: 개인정보처리방침, 이용약관(면책), 문의

## 9. 기술 아키텍처

```
Next.js 15 (App Router) + TypeScript + Tailwind
        ↓
전 페이지 SSG · 서버 런타임 없음
        ↓
Vercel (무료 티어로 충분)
```

### 설계 원칙

**1. 판정·계산 로직은 순수 함수로 완전 분리합니다.**

```
src/lib/
├── constants/
│   ├── 2026.ts                    연도별 요건·요율
│   └── property-score-table.ts    재산점수 등급표 (미확정)
├── dependent/
│   ├── types.ts
│   ├── judge.ts                   판정 로직
│   └── judge.test.ts
└── premium/
    ├── regional.ts                지역보험료
    └── regional.test.ts
```

UI에 로직을 넣지 마세요. 법령이 바뀔 때마다 UI를 뒤져야 합니다.

**2. 연도별 상수를 반드시 분리합니다.**

요건과 요율은 **매년 바뀝니다.** 상수를 코드에 흩뿌리면 1년 뒤 유지보수가 지옥이 되고, 그때 경쟁자에게 밀립니다. 리서치에서 확인한 것처럼 기존 계산기들이 낡아서 죽었습니다.

```ts
// 이렇게
export const RULES_2026 = { healthRate: 0.0719, ... };

// 이러지 말고
const premium = income * 0.0719;
```

**3. 경계값 테스트를 먼저 씁니다.**

2,000만원 ±1원, 과표 5.4억/9억 경계, 형제자매 30세/65세 경계. 이 지점들이 사용자가 실제로 확인하러 오는 곳이고, 틀리면 신뢰를 잃습니다.

## [codex 피드백]

이 문서는 `archive/00-주제-리서치.md`의 초기 경쟁 부재 가정을 이어받은 v1.0 기획서다. 해당 가정과 일부 제도 설명이 이후 조사에서 틀린 것으로 확인됐으므로, 다른 AI는 이 문서를 그대로 구현 명세로 사용하지 말고 아래 정정사항을 우선 적용해야 한다.

### 1. 프로젝트 정의와 차별점 변경

- 31~33행의 `"경쟁 사이트는 전부 계산만 합니다. 우리는 판정합니다. 이게 유일한 차별점"`은 폐기한다. 실제 검색 결과에 피부양자 판정기와 건강보험 자격별 비교 도구가 존재한다.
- 새 한 줄 정의 권장안:

> 퇴직 전후 건강보험 선택을 공식 기준과 공개된 검증 이력으로 설명하는 민간 참고 도구.

- 경쟁력은 `판정이라는 단어`가 아니라 정밀한 조건 처리, 공식 근거 연결, 공단 사례 대조, 갱신 이력과 한계 공개에서 만들어야 한다.

### 2. 서비스 범위와 이름 재검토

- 현재 확정된 런치 범위는 피부양자 판정 1개와 가이드 6편이다. 국민연금·고용보험은 미구현이며 지역보험료·임의계속가입도 검증 완료 전 비공개다.
- 따라서 `사대보험`은 현재 제공 범위보다 넓고 공식 통합 포털처럼 오인될 가능성이 있다. 이름을 서둘러 확정하지 말고 건강보험 세 기능의 검증과 실제 사용자 범위를 확인한 뒤 다시 결정한다.
- 도메인과 이름은 쉽게 바꿀 수 있다는 27행의 전제는 SEO·브랜드·링크 누적 비용을 과소평가한다. 실제 도메인 구매·상표·동명 서비스도 별도 확인해야 한다.

### 3. 사용자 가정과 성공 지표 보완

- 71행의 `"전원의 질문이 예/아니오"`는 과도한 단순화다. 사용자는 판정뿐 아니라 반영 소득연도, 필요한 증빙, 자격 변경 시점, 공단 결과와 차이가 나는 이유, 다음 행동을 함께 필요로 할 수 있다.
- PV·검색순위·애드센스 승인 외에 다음 제품 지표를 추가한다.
  - 판정 완료율과 필드별 이탈
  - 결과 근거 열람률
  - 입력 수정률
  - 공단 공식 확인 경로 클릭률
  - 공단 대조 사례 일치율 및 금액 오차
  - 사용자가 결과를 올바르게 이해하는지 확인하는 테스트
- 검색량, RPM, 11월 계절성, 모바일 비중은 실제 데이터 전까지 가정으로 표시한다.

### 4. 임의계속가입 신청기한 정정

- 173행의 `"퇴직 후 90일 이내 신고"`는 삭제한다.
- 2026년 기준 올바른 안내:

> 지역가입자가 된 이후 최초로 고지받은 지역보험료의 납부기한에서 2개월이 지나기 이전까지 국민건강보험공단에 신청한다.

- 적용기간은 퇴직일 다음 날부터 최대 36개월 범위다. 구체적인 자격과 신청 가능 여부는 공단의 최신 안내를 우선한다.

### 5. 보험료 계산 명세 보류

- 156~157행의 미공개 원칙을 실제 구현과 라우트에 강제해야 한다.
- `property-score-table.ts`의 공제 후 재산 0원 처리(22점 대 0점)가 미확정이고 전월세 환산이 구현되지 않았다. `VERIFIED_AGAINST_NHIS`가 `true`가 되기 전까지 지역보험료 계산기와 임의계속가입 비교를 공개하거나 결과 화면에서 클릭 가능한 링크로 제공하지 않는다.
- 공단 대조는 최소 건수만 채우는 방식이 아니라 다음 대표군을 포함한다.
  - 소득·재산 모두 0
  - 기본공제 바로 아래·같음·바로 위
  - 근로·연금 50% 평가 조합
  - 사업·금융·기타소득 조합
  - 전세·월세
  - 주택금융부채 공제 가능 사례
  - 세대 합산
  - 하한·상한 경계
- 대조 일자, 입력값, 공단 결과, 자체 결과, 차이와 원인을 문서로 공개한다.

### 6. 결과 표현과 법적 오인 방지

- `인정/탈락` 확정형만으로 결과를 제시하지 않는다. 권장 형식은 `"현재 입력하신 내용과 2026년 기준으로는 요건을 충족하는 것으로 계산됩니다"`다.
- 결과와 같은 시야에 반드시 표시:
  - 확인에 사용한 입력값
  - 단계별 적용·미적용 조건
  - 기준연도와 마지막 검토일
  - 공식 근거
  - 민간 참고 도구이며 최종 판정은 국민건강보험공단 심사에 따른다는 고지
- 면책 문구를 12px 푸터에만 두지 않는다. 상수와 레이아웃에 중복된 면책 문자열은 단일 소스로 통합한다.

### 7. SEO 설계 수정

- 계산기 페이지 하나가 모든 검색 의도를 잡을 것이라고 가정하지 않는다. 소득·재산·사업소득·연금·부모·형제자매·탈락 후 보험료 등 질문별 정적 가이드가 답을 제공한 뒤 판정기로 연결되게 한다.
- FAQ 구조화 데이터는 실제 화면에서 볼 수 있는 질문과 답변에만 사용하고, 검색 결과 면적을 차지하기 위한 목적으로 남용하지 않는다.
- 한글 URL이 네이버 색인에 유리하다는 105행의 주장은 근거가 없고 현재 코드도 영문 경로로 전환됐다. 현재 `routes.ts`의 영문 canonical 경로를 기준으로 유지한다.

### 8. 작업 순서 변경

기존의 `못생겨도 2주차 공개 → 색인 시작`보다 다음 순서를 우선한다.

1. 피부양자 법령·공단 기준 재대조
2. 잘못된 임의계속가입 안내 수정
3. 피부양자 대표 사례 테스트와 결과 표현 검증
4. 피부양자 판정만 공개
5. 검색·사용행동 데이터 수집
6. 지역보험료의 재산 0원·전월세 처리 확정
7. 공단 모의계산 사례 대조 및 결과 공개

### 9. 다른 AI에 대한 작업 지침

- 기존 문서의 `검증됨`, `유일함`, `경쟁 없음`, `검색 폭증`, `공단은 안 함` 같은 표현을 증거 없이 반복하지 않는다.
- 공식 자료가 없는 수치는 추정으로 명시한다.
- 법령·요율·신청기한은 매 작업 시점의 공식 원문과 공단 자료로 다시 확인한다.
- 새로운 비평 문서를 추가했다면 발견사항을 원본 문서·코드·디자인 중 최소 한 곳에 반영하고, 반영 여부를 기록한다.
- 이 프로젝트의 광고수익 가능성을 제품 정확성보다 우선하지 않는다.
