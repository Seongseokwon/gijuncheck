## 이 문서의 전제

**도메인 없이 먼저 배포합니다.** 임시 URL로 올려 실제 환경을 확인하고,
도메인이 준비되면 연결합니다.

그런데 임시 URL이 검색엔진에 색인되면 문제가 생깁니다.

- canonical이 아직 없는 도메인을 가리켜 색인이 꼬입니다
- 나중에 본 도메인으로 옮길 때 리다이렉트 부채가 됩니다

그래서 **환경변수 하나로 색인을 차단한 상태로 배포**하고, 도메인 연결 후에
해제합니다. 이 흐름이 이 문서의 핵심입니다.

---

## 0단계 · 배포 전 확인 (5분)

로컬에서 통과해야 Vercel에서도 통과합니다.

```bash
npm run verify     # typecheck + test + build 한 번에
```

- [ ] 테스트 97개 통과
- [ ] `tsc` 통과
- [ ] `out/` 생성

```bash
npm run preview    # out/ 을 정적 서버로 띄움
```

- [ ] 브라우저에서 판정기 → 보험료 → 임의계속가입 동작
- [ ] 가이드 6편 열림

> `next start`는 쓸 수 없습니다. `output: 'export'`라 서버 런타임이 없습니다.
> 자세한 제약은 `next.config.mjs` 주석에 있습니다.

## 1단계 · GitHub 푸시

리모트는 이미 설정돼 있습니다.

```bash
git remote -v
# origin  https://github.com/Seongseokwon/sabohum.git

git push -u origin main
```

푸시가 처음이면 GitHub에서 **저장소를 먼저 만들어야** 합니다. Private로 만들어도
Vercel 연결에 문제없습니다.

`.gitignore`에 `.env*`가 있어 환경변수 파일은 올라가지 않습니다. `.env.example`만
올라갑니다.

## 2단계 · Vercel 프로젝트 생성

1. [vercel.com](https://vercel.com) 로그인 (GitHub 계정으로)
2. **Add New → Project**
3. `sabohum` 저장소 **Import**
4. 설정은 **그대로 두고** Deploy

Next.js는 자동 감지됩니다. 아래 값이 기본으로 잡히는지만 확인하세요.

| 항목 | 값 |
|---|---|
| Framework Preset | Next.js |
| Build Command | `next build` |
| Output Directory | (비워두거나 자동) |
| Install Command | `npm install` |
| Node.js Version | 20.x 이상 |

> `output: 'export'`를 쓰지만 Vercel의 Next.js 빌더가 알아서 처리합니다.
> 혹시 빈 페이지가 나오면 Output Directory를 `out`으로 지정해보세요.

첫 배포가 끝나면 `https://sabohum-xxxx.vercel.app` 형태의 URL이 나옵니다.
**이 URL을 복사해두세요.** 다음 단계에서 씁니다.

## 3단계 · 색인 차단 설정 ★ 가장 중요

첫 배포 상태로 두면 canonical이 아직 없는 사대보험.kr을 가리킵니다.
환경변수를 넣어 임시 URL 모드로 바꿉니다.

**Project → Settings → Environment Variables**

| Key | Value |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | `https://sabohum-xxxx.vercel.app` |

**Environment 체크박스는 세 개 모두 켜세요.**

- [x] Production
- [x] Preview
- [x] Development

> Production만 켜면 Preview 배포에서는 변수가 없어 색인이 열립니다.
> Preview URL은 커밋마다 새로 생기므로 그게 색인되면 정리가 번거롭습니다.

### 재배포해야 반영됩니다

환경변수를 저장해도 기존 배포에는 적용되지 않습니다.

**Deployments → 최신 배포 → ⋯ → Redeploy**

### 확인 방법

재배포 후 두 가지를 봅니다.

1. 화면 상단에 노란 **"테스트 배포"** 배너가 보인다
2. `https://<임시URL>/robots.txt`가 이렇게 나온다

```
User-Agent: *
Disallow: /
```

배너가 안 보이거나 robots.txt가 `Allow: /`면 환경변수가 반영되지 않은 것입니다.
Environment 체크박스와 재배포 여부를 확인하세요.

## 5단계 · 도메인 연결

### 5-1. 도메인 구입

가비아 또는 후이즈에서 `사대보험.kr` 조회 → 구입.
**갱신 자동결제를 켜두세요.** 도메인 만료로 사이트가 죽는 사고가 흔합니다.

### 5-2. 코드 반영

`src/lib/site.ts`의 `PRODUCTION_URL`을 확인합니다.
사대보험.kr이면 이미 맞습니다.

```ts
const PRODUCTION_URL = 'https://xn--vk1bu2qt3cr52a.kr';
```

**다른 도메인을 샀다면** 퓨니코드를 다시 뽑아 넣으세요.

```bash
node -e "console.log(new URL('https://내도메인.kr').hostname)"
```

후보별 퓨니코드입니다.

```
사대보험.kr      → xn--vk1bu2qt3cr52a.kr
피부양자.kr      → xn--or3bo1m2sb6yz.kr
내사회보험.kr    → xn--220b95uuzcq52axza.kr
보험료연구소.kr  → xn--2e0bs9sgkdqyfsqg9w1a.kr
```

수정 후 커밋·푸시하면 자동 배포됩니다.

### 5-3. Vercel에 도메인 추가

**Project → Settings → Domains → Add**

한글 도메인은 **퓨니코드 형태로 입력**하세요. `xn--vk1bu2qt3cr52a.kr`

Vercel이 필요한 DNS 레코드를 알려줍니다. 보통 이렇습니다.

| 타입 | 이름 | 값 |
|---|---|---|
| A | `@` | Vercel이 지정하는 IP |
| CNAME | `www` | `cname.vercel-dns.com` |

### 5-4. DNS 설정

가비아·후이즈의 DNS 관리에서 위 레코드를 입력합니다.

- 전파에 보통 수십 분, 길면 몇 시간 걸립니다
- Vercel Domains 화면에 **Valid Configuration**이 뜨면 완료
- HTTPS 인증서는 자동 발급됩니다

`www`를 쓸지 안 쓸지 정하고, **하나를 대표로 정해 나머지는 리다이렉트**시키세요.
둘 다 열려 있으면 중복 콘텐츠가 됩니다. Vercel Domains에서 설정할 수 있습니다.

## 6단계 · 색인 개방

도메인이 붙었으면 색인을 엽니다.

**Settings → Environment Variables → `NEXT_PUBLIC_SITE_URL` 삭제**

그리고 **Redeploy**.

### 확인

- [ ] 노란 "테스트 배포" 배너가 **사라졌다**
- [ ] `https://사대보험.kr/robots.txt`가 `Allow: /`이고 Sitemap 줄이 있다
- [ ] 페이지 소스의 canonical이 실제 도메인을 가리킨다
- [ ] `https://사대보험.kr/sitemap.xml`에 10개 경로가 있다
      (허브 1 + 도구 3 + 가이드 6, 정책 3개는 제외되는 게 정상)

```bash
# 로컬에서 한 번에 확인
curl -s https://xn--vk1bu2qt3cr52a.kr/robots.txt
curl -s https://xn--vk1bu2qt3cr52a.kr/sitemap.xml | grep -o '<loc>[^<]*</loc>'
```

## 7단계 · 검색엔진 등록

색인이 열린 뒤에 합니다. 하루라도 빠른 게 낫습니다.

### 구글 서치콘솔

1. [search.google.com/search-console](https://search.google.com/search-console)
2. 속성 추가 → **도메인** 선택 (URL 접두어보다 권장)
3. DNS TXT 레코드를 가비아·후이즈에 추가해 소유 확인
4. **Sitemaps** → `sitemap.xml` 제출
5. **URL 검사** → 허브와 도구 3개를 각각 색인 요청

### 네이버 서치어드바이저

1. [searchadvisor.naver.com](https://searchadvisor.naver.com)
2. 사이트 등록 → 소유 확인
   - HTML 파일 방식이면 받은 파일을 `public/`에 넣고 커밋·푸시
   - 파일이 `public/naverXXXX.html`이면 `https://도메인/naverXXXX.html`로 열립니다
3. 요청 → **사이트맵 제출**, **robots.txt 확인**
4. 요청 → **웹페이지 수집**으로 주요 페이지 수동 요청

> **네이버에 대한 현실적 기대치**
> 네이버는 신규 외부 사이트 수집이 느리고 블로그·카페를 우선 노출합니다.
> **초기 트래픽은 구글에서 먼저 옵니다.** 네이버는 3~6개월 뒤에 붙기 시작합니다.
> 한 달 뒤 네이버에 안 나온다고 실망하지 마세요.

### 애널리틱스

- **Vercel Analytics** — Project → Analytics에서 켜면 끝. Core Web Vitals 실측용
- **GA4** — 측정 ID를 발급받아 `layout.tsx`에 스크립트 삽입

GA4를 넣을 때 **판정 완료 이벤트**를 같이 심으세요. 결과가 `eligible`인지,
탈락이면 `failedAt`이 어느 단계인지를 파라미터로 보냅니다.
탈락 사유 분포가 다음 콘텐츠 우선순위를 알려줍니다.

## 자주 막히는 곳

| 증상 | 원인과 해결 |
|---|---|
| 빌드 실패 · Node 버전 | `package.json`의 `engines.node`가 `>=20.9.0`입니다. Vercel Settings에서 Node 20.x 이상으로 |
| 빈 페이지가 나온다 | Output Directory를 `out`으로 지정 |
| 배너가 안 사라진다 | 환경변수 삭제 후 **재배포**해야 반영됩니다 |
| 배너가 안 나타난다 | Environment 체크박스 3개를 모두 켰는지 확인 |
| robots.txt가 여전히 Disallow | 위와 동일. 환경변수 상태 확인 후 재배포 |
| 도메인이 Invalid Configuration | DNS 전파 대기. 몇 시간 걸릴 수 있음 |
| 한글 도메인이 안 붙는다 | 퓨니코드(`xn--`) 형태로 입력 |
| canonical이 임시 URL을 가리킨다 | `NEXT_PUBLIC_SITE_URL`이 아직 남아있음 |
| 서치콘솔에서 "색인 생성 안 됨" | robots.txt가 차단 상태인지, canonical이 다른 도메인을 가리키는지 확인 |
| URL 끝 슬래시가 헷갈린다 | `trailingSlash: true`라 정식 주소는 슬래시로 끝납니다. 슬래시 없이 들어와도 리다이렉트되므로 링크는 슬래시 포함으로 쓰세요 (`routes.ts`가 이미 그렇게 돼 있습니다) |
| 소유확인 파일이 404 | `public/`에 넣고 **커밋·푸시**해야 배포에 포함됩니다. 로컬에만 두면 안 됩니다 |

## 이후 운영 흐름

```
로컬 수정 → npm run verify → git push → Vercel 자동 배포
```

`main`에 푸시하면 Production으로 자동 배포됩니다.
다른 브랜치를 푸시하면 Preview URL이 생깁니다.

### 페이지를 추가할 때

1. `src/app/.../page.tsx` 생성
2. **`src/lib/routes.ts`에 등록하고 `ready: true`**
3. sitemap은 자동 반영됩니다 — 따로 손댈 필요 없음

이 순서만 지키면 sitemap 누락이 구조적으로 발생하지 않습니다.

### 배포 후에도 남아있는 것

- [ ] 공단 모의계산 10케이스 대조 → `VERIFIED_AGAINST_NHIS = true`
      (그때 보험료 화면의 "참고용" 배지가 자동으로 사라집니다)
- [ ] 전세·월세 환산 구현 (시행규칙 원문 확인 후)
- [ ] 애드센스 신청 — 색인 완료 확인 후
- [ ] 매년 1월 요율·요건 개정 반영 (`constants/2026.ts` → `2027.ts`)

## 요약

```
0. npm run verify + npm run preview
1. git push -u origin main
2. Vercel Import → Deploy
3. NEXT_PUBLIC_SITE_URL 설정 (3개 환경 모두) → Redeploy → 배너·robots 확인
4. 실제 폰으로 점검, PageSpeed 측정, 가이드 읽어보기
5. 도메인 구입 → site.ts 확인 → Vercel Domains 추가 → DNS 설정
6. NEXT_PUBLIC_SITE_URL 삭제 → Redeploy → 배너 사라짐 확인
7. 서치콘솔 + 서치어드바이저 등록, sitemap 제출
```

3단계와 6단계가 짝입니다. 3에서 막고 6에서 엽니다.
이 두 개만 순서대로 하면 색인 사고는 나지 않습니다.
