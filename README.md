# 사대보험 (sabohum)

소득이 바뀔 때 내 사회보험이 어떻게 바뀌는지 **판정**해주는 도구.

경쟁 사이트는 전부 "계산"만 합니다. 이 프로젝트의 유일한 차별점은 **판정**입니다.
설계 판단이 흔들릴 때는 이 문장을 기준으로 결정하세요.

## 지켜야 할 규칙 5개

**1. 숫자를 코드에 직접 쓰지 않는다.**

요건과 요율은 매년 바뀝니다. 기존 계산기들이 낡아서 죽은 이유가 이것입니다.
모든 기준값은 `src/lib/constants/2026.ts`에 있고, 로직 파일에는 숫자 리터럴이 없습니다.

새 연도가 오면 `2026.ts`를 복사해 `2027.ts`를 만드세요.

**2. 로직을 UI에 넣지 않는다.**

`judge.ts`와 `regional.ts`는 순수 함수이고 React를 import하지 않습니다.
법령이 바뀔 때 컴포넌트를 뒤지게 되면 유지보수를 포기하게 됩니다.

**3. 경로는 `routes.ts`에만 쓴다.**

페이지를 추가할 때 sitemap 등록을 잊는 게 가장 흔한 실수입니다.
`ROUTES`에 등록하고 `ready: true`로 바꾸면 sitemap이 자동으로 따라옵니다.
컴포넌트에 경로 문자열을 직접 쓰지 마세요.

**4. 결과에는 항상 근거와 기준 연도를 붙인다.**

이 사이트의 자산은 신뢰입니다. 모든 `StepResult`에 `basis`가 있고
`JudgeResult`에 `year`가 있습니다. UI에서 빼지 마세요.

**5. `layout.tsx`에서 임의 상수를 export 하지 않는다.**

Next.js App Router는 layout 파일의 export 필드를 제한합니다.
`SITE` 같은 상수를 여기 두면 빌드가 실패합니다. `src/lib/site.ts`를 쓰세요.

## 남은 결함 2개

**① 공단 대조 검증 미완료**

60등급표는 독립된 두 출처에서 전 구간 일치를 확인했지만, 공단 모의계산과
직접 대조하지는 않았습니다. `VERIFIED_AGAINST_NHIS = false`로 추적 중이고,
`calculateRegionalPremium()`이 `crossChecked: false`를 반환합니다.

특히 **공제 후 재산금액이 0원일 때 1등급 22점인지 0점인지**가 출처마다 다릅니다.
현재는 표 조회에 충실한 22점(A안)을 적용했습니다. 공단 모의계산에
소득 0 · 재산 0을 넣어보면 즉시 확정됩니다.

**② 전세·월세 환산 미지원**

조사한 출처들이 제시한 환산 공식과 그 출처 자신의 계산 예시가 맞지 않았습니다.
추측으로 구현하면 틀린 금액을 보여주므로 의도적으로 비워뒀습니다.
현재 `propertyAmount` 인자는 "환산이 끝난 재산금액 합계"로 취급합니다.
UI에서 그렇게 안내해야 합니다.
